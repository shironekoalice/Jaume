## 2. 核心技术逐项拆解 × 61GB 单卡可落地性

### 2.1 MLA（Multi-head Latent Attention）

- **来源**：DeepSeek-V2 引入，V3 沿用；**V4 换成了 CSA+HCA 混合注意力**。
- **量化效果**：`2607.23054` 实测 **81% KV-cache 削减**（推理侧）。
- **机制可解释性**（`2607.23054`，114M 模型的首次系统性研究）：
  1. cKV 低秩瓶颈学到的是**纯内容表示**——实体身份保留 **98%**，**位置信息被丢弃**（位置由 RoPE 承担）；
  2. induction head **集中在单层**（Layer 12），不像标准 MHA 那样分散；
  3. 存在"语义枢纽层"（Layer 15），SVD 有效秩与 disruption-attribution 同时最高；
  4. **瓶颈全局过度配置：平均只用掉 46% 的容量**。
- **对单卡训练的意义**：MLA 省的是**推理** KV cache，**不省训练显存**。
- **但对小模型有直接启发**：既然瓶颈只用 46%，**小模型应当主动缩小 cKV 秩**——这是一个免费的省参数 + 省带宽的操作。

### 2.2 DeepSeekMoE + 无辅助损失负载均衡

- **对单卡的硬约束**：MoE 训练时**所有专家参数都要驻留**（只是激活部分专家），显存被**总参数**卡死而非激活参数。
  → 61GB 单卡的 MoE **总参数上限约 2.5–3B**，激活参数 0.2–0.4B。想复刻 V3/V4 那种规模需要 100+ 卡。
- **无辅助损失均衡（sequence-wise bias）**：实现成本极低、训练稳定性收益明确，**值得直接抄**。

### 2.3 FP8 混合精度训练

- V3 引入，是其"2.788M H800 卡时"成本的一部分。
- **910B3 不支持 FP8**（BF16/FP16/INT8 级别），Ascend 的 FP8 训练要更新的芯片型号。
  → **单卡 910B3 上不可用，不要写进方案**。

### 2.4 MTP（多 token 预测）—— 与"内部循环思考"最相关的一族

| 论文 | ID / 日期 | 关键结论 |
|---|---|---|
| **How Transformers Learn to Plan via MTP** | `2604.11912` / 2026-04-13（COLM 2026） | MTP 在合成图路径查找、Countdown、SAT 上**稳定优于 NTP**；理论上证明 MTP 诱导**两阶段反向推理**（先注意终点，再反向追溯路径）；机制来自 **gradient decoupling**——MTP 提供比 NTP 更干净的训练信号 |
| **MTP Done Right（Soft-MTP）** | `2610.38331` / 2026-10-28 | 标准 MTP 有缺陷：残差梯度项**随规模增长会淹没**有用的 KL 信号。将其**精确分解**为"KL 自蒸馏项 + 低 SNR 残差"，用 straight-through gradient routing 只回传 KL 项。**167M→1.2B 全尺度提升**，零新增参数、零可测开销，**"一行代码改动"**，同时兼容 DeepSeek 式与 Meta 式 MTP |
| **Adaptive MTP** | `2610.28619` / 2026-10-20 | 在线选择 draft horizon（acceptance survival 刻画），AIME 2025 / GSM8K 上最高 **4.1x** 加速 |

**这两条对你的意义**：
1. `2604.11912` 说明 **MTP 不只是推理加速，它改变了推理回路的结构**（反向推理）。这为"深度内部循环思考"提供了机制层面的正面证据。
2. Soft-MTP 是**当下性价比最高的技术改动**：不花显存、不改架构、一行代码，在小模型上就有可测收益。

### 2.5 内部循环（looped transformer）—— 你的核心方向，最近的正面战场

| 论文 | ID / 日期 | 关键结论 |
|---|---|---|
| **LoopMTP** | `2608.03624` / 2026-08-04 | Looped transformer 复用同一层栈 T 次以固定参数量换取等效深度。现有做法的问题是 **latent overthinking** 与"各轮计算无差别"。LoopMTP 在隐空间建立结构对应：**把第 t 轮的 hidden state 与 t 步之后的 token embedding 软对齐**，再用轻量 gate 保持跨轮信息。**平均准确率相对提升最高 8.1%，训练稳定到 15 loops** |
| **ECHO** | `2610.24766` / 2026-10-17 | 现有 MTP 是**辅助性**的：多 horizon 损失主要训练外挂模块，且**每加一个 horizon 就要多一个模块、多一次前向**。ECHO 取消这两项成本：**backbone 自己的最后一层预测所有 horizon**，监督直接落在生成下一个 token 的参数上；**Dynamic Depth Sampling (DDS)** 按深度衰减的概率采样训练深度。推理时**预训练模型就是自己的 drafter** |
| **Looped Latent Attention (LLA)** | `2607.15456` / 2026-07-16 | Looped transformer 的 KV cache 按 loop 索引存储，成本高。但这个 cache **结构化**：**对固定 token，跨 loop 的 K/V 轨迹是短的低秩轨迹**，而 head / layer 轴要平坦得多。提出后训练 cache codec 存紧凑 K/V latent、只在 attention 读取时重建。同等 cache 预算下优于 head-axis MLA、cross-layer sharing、KV 量化、final-loop reuse；H200 上 4k context 的 batch 从 **32 → 768 sequences**（21.3x 压缩）；MATH-500 上 4x 压缩时准确率 **0.43 → 0.66** |

**这三条合起来给出的判断（很重要）**：

- **"循环深度"这条路已经被做过了**，而且做得很扎实：LoopMTP 报告 +8.1% 且稳定到 15 loops。Jaume 如果只是"loop + MTP"，会被直接判为重复。
- **但 ECHO 和 LLA 各自留了两个缺口**，正好是差异化空间：
  - ECHO 的监督是"第 t 层预测第 t 步之后的 token"，**没有任何关于"循环内部发生了什么"的结构约束**——循环内部表征如何被组织、是否冗余、是否与外部状态解耦，都没有回答。
  - LLA 只证明了"跨 loop 的 KV 低秩"，**没有回答"低秩的那部分是什么"**。
- **Jaume 的天然优势正在这里**：embedding 模型对"表征的组织方式"比纯 LM 更敏感。如果把内部循环做成"**跨循环的表征一致性与冗余度**"的可测量问题（例如：循环 t 的表征是否与循环 t+1 共享子空间？哪些维度在循环间保持不变？），这就是 LoopMTP/ECHO/LLA 都没做的角度，而且能用 Jaume 已有的 slot/表征探针工具直接测。

### 2.6 DSA（DeepSeek Sparse Attention，V3.2 引入）

- 每层前有一个 lightning indexer，对整个 cache 打分并保留 top-k=**2048**；长上下文时**瓶颈是 indexer 扫描本身**，不是稀疏注意力。
- `2611.03768` Multi-layer Indexer（2026-11-02）：相邻层选择的 token 几乎相同 → 一层可以**复用上一层的选择**，从而让 indexer 与本层 attention 并行执行；无需重训、无新权重。
- **定位**：纯推理优化，对单卡训练无帮助；但对"长上下文 + 内部循环"的服务形态有用。

### 2.7 Muon 优化器（V4 新增）—— 对 61GB 单卡是**实打实**的收益

| 优化器 | 每参数字节（fp16 参数 + bf16 梯度 + fp32 master） | 61GB×0.75 可训参数 |
|---|---|---|
| AdamW | 2 + 2 + 4 + 4(m) + 4(v) = **~16–18** | **~2.6B** |
| Muon | 2 + 2 + 4(momentum) + 4(master) ≈ **~12** | **~3.8B** |

- V4 明确使用 Muon 以"更快收敛 + 更强训练稳定性"。
- **[细节未核]**：Muon 在这个栈里的确切 buffer 数与是否需要 fp32 master 未核；但"比 AdamW 省 momentum 一个 buffer"是确定的。
- **结论**：换成 Muon，单卡可训规模**从 ~2.6B 抬到 ~3.8B**，约 +45%。这是本次核查里对"你能训多大模型"影响最大的一条。

## 3. 视觉-语言方向

| 论文 | ID / 日期 | 关键结论 |
|---|---|---|
| **DeepSeek-OCR 2 / DeepEncoder V2** | `2601.20552` / 2026-01-28 | 传统 VLM 按**光栅扫描**顺序、固定位置编码喂视觉 token，与人类语义驱动的扫描方式不符。DeepEncoder V2 让编码器**按图像语义动态重排视觉 token**（因果式），用**两个级联的 1D 因果推理结构**实现，目标是真正的 2D 理解。代码与权重已公开（GitHub deepseek-ai/DeepSeek-OCR-2） |
| **MHA2MLA-VLM** | `2601.11464` / 2026-01-16 | 把现成 VLM 转成 MLA 的**参数高效**方案：(1) **modality-adaptive partial-RoPE**（选择性屏蔽非必要维度，兼容传统与多模态）；(2) **modality-decoupled 低秩近似**（视觉与文本 KV 空间独立压缩）。关键经验：**最小化"输出激活误差"比最小化"参数距离"更能减少性能损失** |

**对 61GB 的意义**：MLA 迁移到 VLM 有现成配方；61GB 上最稳的 VLM 训练形态仍是**冻结 LLM + 训 projector（+ ViT LoRA）**。

## 6. 对 Jaume 的具体建议（明确取舍）

### 6.1 两条线都要，技术栈要分

- **Jaume-Embedding**（现有）：**不要**把 DeepSeek 的训练技术栈搬过来。embedding 模型的训练目标（对比学习 / Matryoshka / 决策头）与 LM 预训练不共享问题。可借鉴的只有 **Looped Latent Attention 的"跨循环 KV 低秩"**——如果给 embedding 模型加循环深度，缓存同样会低秩。
- **Jaume-LLM**（新增）：用 **Soft-MTP + Muon + LoopMTP/ECHO 思路 + 无辅助损失均衡**。这是性价比最高的组合。

### 6.2 "深度内部循环思考"必须正面回答 LoopMTP

LoopMTP 已经把"loop + MTP"做了并报告 +8.1%。Jaume 要立住，需要一个它没有的角度。基于 §2.5 的分析，我建议的差异化问题：

> **循环内部的表征是怎么被组织的？**
> - LoopMTP 用隐空间软对齐**监督**循环，但没有**测量**循环内部发生了什么；
> - LLA 证明跨 loop 的 KV **低秩**，但没说低秩的是什么；
> - **可测的候选问题**：循环 t 与循环 t+1 的表征共享多少子空间？哪些维度在循环间**保持不变**（应当对应"稳定的事实"）？哪些维度在**变化**（应当对应"推进的中间推理"）？循环是否**过度思考**（多轮后表征不再改变）？

这个问题恰好可以用 Jaume 已有的表征探针 / slot 工具直接测，而且**即使结论是负结果也是可发表的**（"内部循环的增益不来自更深的计算，而来自……"）。

### 6.3 规模与成本（概要，详见后续算力规划）

- 换 **Muon** 后单卡可训规模 ~2.6B → ~3.8B。
- 但**不要从零训 ≥1.5B × 30B tokens**（>100 卡时）。建议 **0.6B–1.5B 规模 + 10–20B tokens**，把预算留给内部循环实验本身。
- 更省的路：**开源基座 + DeepSeek 技术做领域继续预训练**。SLAI T-Rex 验证了"求解器验证的合成数据 + CPT/SFT"在昇腾上可行。

### 6.4 VLM

- 用 **MHA2MLA-VLM** 的思路把 MLA 迁到 VLM（若你有既有 VLM）；否则 61GB 上直接"冻结 LLM + 训 projector"。
- **DeepSeek-OCR 2 的"视觉 token 因果重排"**是一个有意思但更大的改动，建议放在 VLM 阶段的后续。
