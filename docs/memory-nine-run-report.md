### 0.1 但有一个更重要的限定

## 3. 一个值得注意的观察

`carried − static` 虽未显著，但**方向在 9 次中 100% 一致为负**，
且均值 −0.021（约为 static 均值的 11%）。

**这不是"无差异"，而是"记忆传递有轻微负向"**——但因 CI 含 0，按协议不能称为显著。

`carried − shuffled` 接近 0（−0.003），说明
**状态内容本身既不帮忙也不明显伤害**；负向主要出现在与 `static` 的比较上。

## 4. 为什么这不能解释为"机制无效"

### 4.1 训练目标与评测不一致（协议缺陷，已事先声明）

| 项 | 值 |
|---|---|
| 训练正类 | `gold_blocks[0]`，**只有 1 个块** |
| 评测指标 | 集合 F1，要求 **2–3 个块** |
| 测试集 gold 块总数 | **374**（训练信号只覆盖每条的 1 个） |

模型从未被训练去寻找完整集合，而评测却按集合完整性计分。

### 4.2 模型根本没学会任务

```
loss: 2.4040 → 2.3965 → 2.3685     (ln(12) = 2.479)
```

所有条件的 F1 落在 **0.143 – 0.228** 之间，
而**零训练 BM25 基线在同样数据上是 0.281 – 0.321**。

**训练过的模型（0.14–0.23）低于零训练的 BM25（0.28–0.32）。**

这与我之前在 Qasper 全量上观察到的现象一致：
模型在这个任务上没有学到"问题↔块"的匹配。

### 4.3 因此的准确表述

> 在**该训练目标与训练预算**下，模型未能学会跨块证据选择任务；
> 在此条件下，跨块状态传递**未表现出可检测的收益**。
>
> 这不构成对 JM-R 机制的否定。

## 6. 下一轮必须修正的三项（按优先级）

1. **训练目标与评测对齐**：改用多标签 BCE 或对集合内所有块给正信号，
   而不是只取 `gold_blocks[0]`；
2. **先把 concat/无记忆基线训练到超越 BM25（0.32）**，
   在此之前不比较任何记忆条件——这是"任务可学"的门槛；
3. **降低任务难度或增加预算**：当前 loss 停在 ln(块数)，
   不排除需要更长训练或更小的候选空间。

## 7. 诚实标注的局限

1. 训练未成功，**所有条件差异都不可解释为机制效应**；
2. 测试集仅 168–179 条，效应量 0.02 在噪声范围内；
3. `static` 与 `concat` 在本实现中数值相同，实际只有**两条**独立臂
   （carried / static / shuffled 中 static 涵盖两者）；
4. 单块数上限（12）与单 epoch 预算（3）未经调优。
