## 0. 对上一轮结论的修正（采纳评审意见）

SciFact 未达标**不能归因于样本量**。已修改为四个并列解释（不可择一）：

1. 测试集规模（228 条）；
2. 对初始化敏感（种子 1 的 reset/shuffled 异常偏高）；
3. 对数据划分敏感（当前仅单一划分）；
4. 机制本身不适用于短摘要任务（两块一次即可读完）。

**若要区分 (1) 与 (2)(3)，需要换多种数据划分（同规模测试集），而不只是加种子。**

## 1. 为什么选 Qasper

| 维度 | SciFact（已做） | **Qasper（本轮）** |
|---|---|---|
| 文本长度 | 摘要（数百 token） | **全文论文（通常 3k–10k token）** |
| 信息位置 | 摘要内 | **分散在多个章节** |
| 证据标注 | 有（句级） | **有（evidence + highlighted_evidence）** |
| 块数 | 2 | **可控（按章节/段落切 4–16 块）** |
| 能否测"长程收益" | ❌ 两块一次读完 | ✅ **可控制距离** |

**Qasper 数据已下载**：`data/qasper_official/`
- train：**888 篇论文 / 2593 问题**
- dev：368 篇 / 1143 问题（需确认）

字段确认：`answers[i].answer` 含
`free_form_answer`、`extractive_spans`、`evidence`、`highlighted_evidence`、`unanswerable`、`yes_no`。

## 2. 四条成功标准（事先固定，不可事后调整）

### S1 任务可学
```
concat 基线（全部块一次读完）的答案准确率 显著高于随机/常量基线
```
**若 concat 不达标 → 停止，不测记忆。**

### S2 记忆有效
```
carried 在 3 个种子上均优于 reset 和 shuffled，
且配对差值 bootstrap 95% CI 不含 0
```

### S3 长程收益（**本轮的核心**）
```
按"证据所在块"与"提问位置"的距离分层：
  d=1（相邻块）、d=3、d≥6（远距离）
carried − reset 的差值应随 d 增大而增大
```

**这条必须排除的替代解释**（评审要求）：

| 混淆因素 | 控制方式 |
|---|---|
| 分块方式 | 所有条件用**完全相同**的分块 |
| 训练预算 | 同一 epoch 数、同一 batch、同一 lr |
| 输入长度 | 记录每条件的 token 数；concat 若被截断需报告截断率 |
| 上下文上限 | 报告 concat 的截断率，若 >10% 则 concat 不算公平参照 |

### S4 评价可靠
```
按论文划分（train/val/test 无共享 paper_id）
保留证据位置（记录证据落在第几块）
独立验证集用于早停
报告配对差值 + bootstrap CI
```

## 3. 数据接口检查（本轮先做，不改模型）

### 3.1 可复用的代码

| 模块 | 状态 | 说明 |
|---|---|---|
| `RecurrentMemoryPooling` | ✅ 复用 | 8 槽，`memory_output` 开关 |
| `base.encode(ids, mask, state)` | ✅ 复用 | 返回 (pooled, aux, next_state) |
| `base.projection` + L2 | ✅ 复用 | **必须保留**（SciFact 阶段曾漏掉） |
| 四条件骨架 `eval_scifact.eval_one` | ⚠️ 改 | 需支持 N 块而非固定 2 块 |
| `Head`（3 类） | ⚠️ 改 | Qasper 是抽取式/自由式答案，不是 3 分类 |

### 3.2 任务形式选择（**待定，需确认**）

Qasper 原生是开放问答，直接做生成不现实（350M 编码器）。可行方案：

**方案 Q-A：证据块分类（推荐先做）**
```
输入：问题 + 全部块（经记忆）
输出：哪一块包含答案证据（多选一）
指标：Accuracy@1、MRR
```
- 优点：与现有四条件框架同构，`Head` 只需换成相似度打分
- 优点：**天然带距离维度**（证据块位置可分层）
- 缺点：测的是检索，不是生成

**方案 Q-B：答案类型分类**
```
输入：问题 + 全部块
输出：答案类型（数值/实体/是-否/不可答）
```
- 优点：近似 3 分类，改动小
- 缺点：信息量低，可能不依赖跨块

**方案 Q-C：抽取式答案打分**
```
候选：evidence 中的句子 + 干扰句
输出：选哪个句子是答案
```
- 优点：最接近真实任务
- 缺点：候选取自证据，可能泄漏"证据在哪"

**建议先做 Q-A**：最干净、最容易分层检验 S3。

## 4. 分块策略（决定 S3 能否成立）

```
按论文章节顺序拼接全文 → 按固定 token 长度（如 256）切块
记录：每个块属于哪一章节、是否含证据句
```

**距离定义**（S3 需要）：
```
d = |证据所在块 - 问题被提出的位置|
```
由于 Qasper 的问题不依附于特定块，改用：

```
d = 证据块索引（从第 1 块到第 N 块）
```
即**证据越靠后，模型需要跨越的块越多**。这是可控且可解释的"距离"。

或者更强的方式：
```
把"问题"放在检索阶段之后，d = 证据块与最后一个块的跨度
```

**这一点需要确认后再实现**，因为它直接决定 S3 的度量是否成立。

## 5. 实测约束（已执行，改变了设计）

### 5.1 Qasper 长度（`scripts/measure_qasper_lengths.py`）

```
papers=888
token length  min=187  p25=3539  median=5169  p75=6516  p90=8336  max=36505
窗口 512 时超出比例: 99.7%
256-token 块：每篇论文中位数 21 块
```

**结论：concat 若按"全文拼接"必然严重截断，不是公平参照。**
按评审决定，`concat` 改为**各块独立编码后平均聚合**——与 `carried` 看到完全相同的块，
唯一差别是状态是否流动。

### 5.2 显存与吞吐（实测，决定了配置）

逐块 batch-1 前向时 **GPU 利用率仅 4%**。改为"同位置块跨论文并行"后达 99%，
但显存成为硬约束：

| 配置 | 吞吐 | 峰值显存 | 可行 |
|---|---|---|---|
| maxlen=256, bps 4 | — | **30GB** | ❌ OOM |
| maxlen=192, bps 4 | 246 papers/min | 14.8GB | ⚠️ 紧 |
| **maxlen=128, bps 6** | **332 papers/min** | **12.5GB** | ✅ **采用** |
| maxlen=128, bps 8 | 165 papers/min | 17.1GB | ❌ 超限 |

**因此块长从 256 降到 128**，数据按 128 token 重新分块。

### 5.3 块数上限与样本量

`max_blocks` 决定保留多少样本（证据须在该范围内）：

| max_blocks | train | test |
|---|---|---|
| 8 | 228 | 73 |
| 12 | 402 | 122 |
| 16 | 541 | 165 |
| **20** | **695** | **210** |
| 24 | 820 | 240 |

**采用 max_blocks=20**：兼顾样本量与显存。
