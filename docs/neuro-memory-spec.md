## 1. 方向定位

Jaume-NM 研究**类脑结构如何承载记忆**，与另两个记忆相关方向边界如下：

| 方向 | 研究对象 | 记忆位置 | 状态 |
|---|---|---|---|
| Jaume-Memory（JM-S/JM-R） | 神经状态通道能否承载跨输入信息 | 模型内部（可学习槽/循环状态） | 已结题，两机制均未通过 |
| **Jaume-NM**（本文） | **结构化关系记忆**如何编码、绑定与泛化 | 模型内部（显式结构 + 内容） | 方向定义阶段 |
| metamem | 无查询时判断"什么值得记住"（写入策略） | 模型外部 | 暂停，待迁服务器 |

**关键区分**：Jaume-Memory 问的是"定长向量够不够"；Jaume-NM 问的是"记忆该以什么**结构**存在"。
metamem 则完全不改模型。三者不可互相替代，也不应合并为一个大实验。

## 2. 为什么从这里开始（来自 JM-S/JM-R 的教训）

Jaume-Memory 的负结果提供了三条对本方向有约束力的经验，**它们直接决定本文的实验设计**：

| 来源 | 事实 | 对 Jaume-NM 的约束 |
|---|---|---|
| `memory-report.md` §6.1 | 输出路径从不读取状态，`pooled_A` 与 `state_A_mean` 逐位相同 | **任何结构必须结构性参与输出**，不能留绕开它的通路 |
| `memory-report.md` §6.2 | 坍缩发生在状态更新步（读出余弦 0.765 → 更新后 0.99），不在读出步 | 更新规则必须是选择性的，不能是纯残差累加 |
| `memory-report.md` §6.3 | 门控训练后退化为常数（sd 0.132 → 0.006，权重变化 141%） | **必须监控门控对输入的标准差**，并入验收项 |
| `memory-report.md` §6.4 | 强制改门控值救不回性能 | 先证明状态内含任务信息，再谈融合机制 |
| `memory-report.md` §4.1 | carried 0.492 ≈ 公平 concat 0.491 | **联合编码对照组必须保留**，否则无法排除"绕过记忆" |

## 3. 外部参考：Hippoformer（ICLR 2026）

### 3.1 身份与状态 **[已核实]**

- 标题：Hippoformer: Integrating Hippocampus-inspired Spatial Memory into Transformer
- 会议：ICLR 2026 Poster（OpenReview `hxwV5EubAw`，ICLR 虚拟会场 poster 10008006）
- 无 arXiv 版本（arXiv API 查询 Hippoformer 返回 0 结果）
- 已知代码仓库指向存疑 **[待核实]**（搜索结果指向的 `Gustav-Proxi/HippoFormer` 未能与官方页面互相印证）

### 3.2 它解决的问题（官方摘要原文要点）

> Transformers 的 key–value memory "lacks inherent spatial priors, constraining their capacity for spatial reasoning."

> 神经科学依据："the medial entorhinal cortex provides structural codes and the hippocampus binds them with sensory codes."

> 既有类海马模型（如 TEM）的缺陷："inefficiencies due to outer-product operations or context-length bottlenecks in self-attention."

### 3.3 方法：mm-TEM + Transformer **[部分已核实]**

| 组件 | 官方摘要表述 | 状态 |
|---|---|---|
| mm-TEM | "an efficient and scalable structural spatial memory model that leverages **meta-MLP relational memory** to improve training efficiency" | **[已核实]** 组件存在与作用 |
| 网格表示 | "can form **grid-like representations**, and reveal an intriguing link between **prediction horizon and grid scales**" | **[已核实]** 现象被报告 |
| 泛化 | "generalizes well on **long sequences, large-scale environments, and multi-step prediction**" | **[已核实]** 任务范围 |
| 整体架构 | "integrates mm-TEM with Transformer to combine structural spatial memory with precise working memory" | **[已核实]** 分工表述 |
| Meta-MLP 的具体形式（是否 fast weights、如何降低外积成本） | 摘要只说"提高训练效率" | **[待核实]** |
| 路径积分（path integration）作为结构编码来源 | **官方摘要中未出现该表述** | **[待核实]** |

> **需修正的既有转述**：此前对 Hippoformer 的描述称 mm-TEM "通过路径积分获得结构性编码"。
> 官方摘要的实际表述是内嗅皮层提供**结构编码**、海马将其与**感觉编码绑定**；未提路径积分。
> 该细节可能存在于正文，但在读到正文前不应作为事实引用。

### 3.4 迁移到 Jaume-NM 时必须承认的落差 **[本系列主张]**

Hippoformer 解决的是**空间预测**（2D/3D 环境中的导航与多步预测）。
它证明的不是"类脑记忆优于普通记忆"，更不是"该机制适用于文本记忆"。

对于 Agent 场景，可迁移的**假设**是：

- 记忆不必被压成通用内容压缩器，可以保留任务结构（谁在何时决定、计划与事件的依赖、环境变化后哪些旧信息失效）；
- 这类关系未必适合压进一个持续累加的稠密向量。

这些是**待检验假设**，不是已知结论。

## 4. 研究问题（NM-Q1…Q3）

### NM-Q1（主问题）：结构化关系记忆能否在文本任务上带来可测量的增量？

> 在受限容量下，显式维护"实体—关系—事件"结构，相比单一的稠密状态，
> 能否在**跨事件关系**与**干扰抵抗**任务上取得联合编码做不到的收益？

判定必须同时满足（沿用 JM-R 的对照纪律）：

```
结构化记忆有效 ⇔ 优于 ①无记忆 且 ②传入错误结构的对照
                 且 不劣于 ③联合编码（否则收益只是"多给了上下文"）
                 且 3 个种子同号、bootstrap 95% CI 不含 0
```

**③ 是硬约束**：JM-R 的合成任务上 carried 0.492 与公平 concat 0.491 无差异，
说明"看起来有效的记忆"很可能只是另一种形式的联合编码。NM-Q1 若重复这一点即判失败。

### NM-Q2：结构编码的泛化边界

在训练环境/实体规模之外，结构记忆是否仍有效（Hippoformer 报告了 large-scale environments 的泛化，对应到文本即**未见的实体组合与更长的依赖距离**）。

### NM-Q3：结构的更新规则

当事实被更新（同一实体属性改变、旧计划作废）时，结构记忆能否**覆盖而非累加**。
这直接对应 JM-R §6.2 的坍缩病理：纯残差更新会把新旧混在一起。

**首轮只做 NM-Q1**。Q2/Q3 在 Q1 通过后才启动。

## 5. 首轮方案（NM-PoC）

### 5.1 任务：最小结构化依赖任务

**不从真实文档开始**（JM-R 的教训：SciFact 摘要短、块间依赖弱，无法保证"必须跨块"）。
先在合成任务上建立可判定的基线，再迁移。

任务形态（沿用 `memory-p1-synthetic-task.md` 的验收纪律）：

```
环境设定块（结构化）：
  ORION 的密钥是蓝色；VEGA 的密钥是红色；VEGA 的负责人是 K；...
更新块：
  VEGA 的密钥改成了绿色。
查询：
  VEGA 现在应该用什么颜色的密钥？（正确：绿色）
```

必须满足的构造要求（缺一不可）：

| 要求 | 实现 | 为什么必须 |
|---|---|---|
| 必须跨块 | 单看任一块都无法作答 | 任务成立的前提 |
| 必须处理更新 | 存在被覆盖的旧值作为干扰项 | 对应 NM-Q3 的病理 |
| 实体随机化 | 大词表随机采样 | 防记忆固定实体 |
| 测试隔离 | 测试用训练未见的实体组合与模板 | 防模板记忆 |
| 反捷径 | 报告 `chunk_overlap_ceiling` 与 `lexical_leakage` | JM-R conflict 探针曾词面上限 1.00 |
| 无状态对照必须失败 | 基线 ≈ 随机 | 任务成立的硬判据 |

### 5.2 对照臂（强制，缺一不可）

| 臂 | 说明 | 作用 |
|---|---|---|
| A0 `no_memory` | 只编码当前块 | 下界 |
| A1 `dense_state` | JM-R 式稠密状态（复现已知失败） | **锚点**：结构化机制必须显著优于它 |
| A2 `concat` | 全部块联合编码 | **信息可用性上限**；结构化机制不得超过它太多才算"独立收益" |
| A3 `structured` | 候选方案：显式实体—属性—关系表 + 检索 | 待检验机制 |
| A4 `shuffled_structure` | 传入错误/打乱的结构 | 排除"额外参数"造成的假收益 |

**判读逻辑**：A3 > A0 且 A3 > A4 → 结构内容有用；A3 ≈ A2 → 收益可能只是"多给了信息"，
必须补充**同容量**对照（如 A2 限流到与 A3 相同的 token 预算）才能声称独立收益。

### 5.3 实现路线（三层递进，前层不过不进）

| 层 | 方案 | 参数量 | 目的 |
|---|---|---|---|
| N1 | 冻结骨干 + 规则抽取的实体—属性表 + 符号检索 | 0（无训练） | **上界探针**：若规则方案都做不到，任务或数据有问题 |
| N2 | 冻结骨干 + 可学习结构读写头（小参数） | <5M | 检验"可学习结构"是否必要 |
| N3 | 端到端训练结构模块 | ~10M | 仅 N2 显示明确收益后启动 |

**N1 必须先做**：它成本极低（无需训练），能立刻区分"任务不可解"与"机制不够好"。

### 5.4 指标与验收

| 指标 | 阈值 / 说明 |
|---|---|
| 主指标 | 查询准确率（多候选，报告随机基线） |
| 更新正确率 | **单独报告**被覆盖项的正确率（NM-Q3 的核心） |
| 干扰抵抗 | 加入无关新块后准确率下降幅度 |
| 门控/读写统计 | 读写权重对输入的标准差（防 JM-R §6.3 式退化） |
| 状态可辨识性 | 线性探针：结构表示对当前实体的可辨识性 |
| 反捷径 | `chunk_overlap_ceiling` ≤ 0.25、`lexical_leakage` ≤ 0.10 |
| 统计 | ≥3 种子，配对差 + 按样本 bootstrap 95% CI |

### 5.5 Go / No-Go（预注册）

- **Go（进 NM-Q2）**：A3 显著优于 A0、A4、A1；更新正确率显著高于 A1；且 A3 在**同容量**对照下仍优于 A2。
- **部分 Go**：A3 > A1/A4 但 ≈ A2 → 结论记为"结构只是更省上下文的联合编码"，进二期前必须解决容量对照。
- **No-Go**：A3 ≈ A1 或 ≈ A4 → 记录负结果，结构设计回炉，不追加算力。

## 6. 资源与执行约束

| 项 | 要求 |
|---|---|
| 硬件 | 单卡即可；350M 骨干 + 小结构模块，12GB 显存内 |
| 本地核显 | 仅用于 N1（无训练）与流水线验证；训练迁服务器 |
| 数据 | 合成任务自生成（无许可问题）；真实文本阶段再用 SciFact/Qasper |
| 时间预算 | N1 ≤ 1 天；N2 ≤ 3 天；N3 仅 Go 后启动 |

**当前算力现实**：本机核显实测 350M 训练约 7.8 pairs/s（4060 Ti 的 1/3～3/4），
不适合跑 3 种子 × 多臂矩阵。N2/N3 必须上服务器。
