## 0. 一句话结论

**Jaume 的文本 encoder 可以被复用作 VLM 骨干。** 冻结全部 369M 参数、
只训练 1.2M 的视觉 projector，视觉计数任务准确率达到 **99.5%**；
解冻顶部 4 层后达到 **100%**。

---

## 1. 为什么要做 VLM（与循环方向的关系）

循环方向的最终结论是：在 350M 上我们构造的全部任务都不是深度受限的，
因为注意力天生擅长并行可解的问题 —— 链长（传递闭包）、运算步数（并行宽度）、
输入长度（并行归约）都被一次前向解决了。

**视觉模态可能提供循环真正需要的那类任务**：空间关系、逐位置扫描、
需要维护不可压缩中间状态。所以 VLM 线同时服务两个目标：

1. 产品：Jaume 从纯 embedding 扩展到多模态；
2. 研究：为循环/深度受限任务提供新的实验场。

## 2. Stage 0：视觉桥接能通吗（已完成，通过）

### 2.1 设计

图像 (32x32) -> CNN stem (0.67M) -> 64 patch 向量
           -> Projector (0.53M) -> 16 token (512 维)
           -> 与文本 token 拼接 -> Jaume encoder -> mean pool -> 线性头

任务：合成形状计数。N 个形状随机放置，问 "how many circles?"，答 1..6。

选计数任务的理由：它不是并行可解的（必须逐位置扫描并累积），
恰好是循环方向缺的那类结构。

### 2.2 结果（910B3，6000 训练 / 600 验证，8 epoch）

| 配置 | 可训练参数 | val 准确率 |
|---|---|---|
| **V1 全冻结**（只训 projector） | 1.2M | **0.995** |
| **V2 解冻顶部 4 层** | ~75M | **1.000** |

多数类基线 = 0.167（标签严格均衡，1..6 各 1000 个）。

### 2.3 三条结论

1. Jaume encoder 可以吃视觉信号。1.2M 的 projector + 全冻结骨干就到 99.5%。
2. 解冻顶部 4 层是干净的提升（99.5% -> 100%），与主流 VLM 做法一致，
   没有灾难性遗忘。
3. 全解冻反而更差（V3 实验 0.473 vs V1 0.610）—— 292M 参数在 6000 样本上
   过拟合会破坏预训练能力。这是 350M + 小数据的经典限制，
   也说明解冻顶部几层是正确折中。

### 2.4 方法论教训（必须记录）

第一次跑时 V1 准确率卡在 0.61 且不涨，看起来像桥接失败，实际是标签分布有偏：
max_shapes=6 时答案 0 占 30.6%、1 占 35.5%,"永远猜 1" 就得 35.5%。
修正为严格均衡（每次恰好 target 个目标形状）后，同一配置从 0.61 跳到 0.995。

教训：合成任务的标签分布必须先验证。这与循环方向的经历一致
（链式/寄存器任务都是 0.0000，也是先验证数据才确认不是 bug）。

### 3.2 中期：VLM x 循环（本方向的研究价值）

计数任务天生是并行不可解的（必须逐位置扫描累积）。如果 8L vs 16L
在计数任务上出现深度差异（循环方向从未做到过），就找到了循环真正
可能有用的任务族。判据沿用 loop-spec 8.10：先看 8L/16L 是否有差异，
再谈循环。

## 4b. 深度扫描结果：视觉计数同样在 8L 饱和（2026-11-08）

Stage 0 的任务是"颜色 x 形状计数"（13 类答案）。在它上面做 8L/16L/32L
深度扫描，检验视觉通道是否会制造文本任务没有的深度需求：

| 深度 | 最好 val acc | 每 epoch |
|---|---|---|
| 8L | 0.983 | 56s |
| 16L | 0.986 | 96s |
| 32L | 0.987 | 195s |

16L 只比 8L 高 0.003（阈值 0.01），32L 再高 0.001 但耗时翻倍。
**视觉计数没有制造深度需求**，和文本侧的 `loop-spec.md` 8.9/8.11b 一致。

含义：VLM 方向要继续，必须换"真正需要多步空间推理"的任务
（如多跳视觉关系、图结构或多图对比），而不是靠堆层数解决问题。
