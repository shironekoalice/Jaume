## 1. 检查 A：筛选泄漏 —— **FAIL，已修复**

### 1.1 泄漏的内容

原构造脚本 `make_qasper_composition.py` 含筛选：

```python
sc = bm25_rank(question, blocks)
top = argmax(sc)
if top in evidence_blocks:      # 证据块位置来自官方标注
    drop                        # ← 这一条是泄漏
```

**为什么这是泄漏**：它不需要标签，但**需要基线的表现**。
该筛选在**划分之前**对所有样本执行，于是测试集变成
"BM25 失败的样本集合"。**测试集被针对基线表现选择了。**

### 1.2 损害量化

| | 先前报告 | 无偏（去掉该筛选） |
|---|---|---|
| 保留样本 | 592 | **881** |
| test 规模 | 124 | **171** |
| **BM25 F1（test）** | **0.140** | **0.302** |

**先前报告的 BM25 基线被低估 2.2 倍。**

### 1.3 修复

**移除 BM25 筛选**，仅保留只依赖标注或文本的筛选：

| 筛除条件 | 依赖信息 | 判定 |
|---|---|---|
| 证据少于 2 条 | 官方标注 | ✅ 允许 |
| 证据全在同一块 | 官方标注 | ✅ 允许 |
| 证据冗余（Jaccard≥0.5） | 官方标注 | ✅ 允许 |
| 问题原文包含证据 | 文本 | ✅ 允许 |
| ~~BM25 单块胜出~~ | **基线表现** | ❌ **已移除** |

**必须使用 `data/qasper_comp_clean/`，不得使用旧的 `qasper_comp/`。**

### 1.4 修复后的准入重新评估

无偏 BM25 F1 = **0.302**，仍低于"0.45 可用"门槛，
但**理由与之前不同**：不是"BM25 完全失效"，而是
"BM25 只能解释约 30%，剩余需组合能力"。

## 3. 冻结的成功标准

### 3.1 主要比较（仅这两项）

```
primary_1:  carried − static      （static = reset = concat）
primary_2:  carried − shuffled
```

**两项都必须报告，不得只挑表现更好的那一项。**

### 3.2 训练配置

| 项 | 值 |
|---|---|
| 数据划分 | **3 个固定的论文级划分**（seed 0/1/2 划分） |
| 每个划分的种子 | **3 个预先固定**（seed 0/1/2） |
| 总运行次数 | **9** |
| 模式 | carried / static / shuffled（同一 checkpoint 上评测） |
| 块数上限 | 12 |
| 每步论文数 | 4 |
| epoch | 3 |
| lr | 1e-4 |
| 初始化 | 同一 base checkpoint（`350m-mlm`） |

**不追加、不删减、不替换任何一次运行。**

### 3.3 正式成功（必须同时满足）

```
S1  三个划分上，mean(carried − static) 均 > 0
S2  三个划分上，mean(carried − shuffled) 均 > 0
S3  跨划分汇总效应的 95% CI 不包含 0（两项比较各一个）
S4  结论在全部 9 次运行上成立，而非仅最佳种子
```

### 3.4 统计汇总方法（事先确定）

**聚类单位是论文，不是样本，也不是运行次数。**

```
1. 每个 (划分, 种子) 内：按测试样本计算配对 F1 差值
2. 每个划分内：对该划分的 3 个种子取均值，得到 d_split
   - 同时报告 3 个种子各自的 d_seed（不隐藏波动）
3. 跨划分汇总：对 3 个 d_split 计算均值与 bootstrap CI
   - bootstrap 重采样单位 = 论文（paper_id），尊重聚类
   - 不使用"9 次 = 9 个独立实验"的说法
4. 同时报告：逐划分、逐种子、按论文聚类的配对统计
```

**明确禁止的推断**：

- ❌ 把 3 个划分的 CI 当作 9 次独立实验的证据
- ❌ 把 9 次训练当作 9 个独立数据集
- ❌ 只报告最佳种子

### 3.5 主要指标

**测试集集合级 F1**，评分实现固定为：

```
pred = 模型选出的块集合（top-k，k = |gold|）
gold = 标注证据块集合
F1   = 2·|pred∩gold| / (|pred| + |gold|)
```

**所有条件使用同一实现，不得中途更换。**

## 4. 结果解释（事先写定）

| 结果 | 结论 |
|---|---|
| 满足 S1–S4 | **真实长文档跨块组合任务上的初步机制证据**（仍不等于通用长程记忆） |
| 方向为正但 CI 含 0 | **结果不确定**：不宣称有效，也不断言无效 |
| 只优于 static、不优于 shuffled | **不能证明**正确状态传递带来收益 |

## 6. 一个必须记录的失败模式

第一格 loss 停在 2.37（≈ln(12)=2.48），说明模型**没有学会选择证据块**。

这与之前 Qasper 全量的现象一致（loss 停在 ln(块数)）。
可能原因（未验证）：

1. 3 epoch 不足以学会这个任务；
2. 任务对 350M 编码器过难（问题是抽象提问，证据是具体发现，语义跨度大）；
3. 训练目标（用 gold_blocks[0] 作为唯一目标）与评测（集合 F1）
   不完全一致——**这是一个已记录的设计不匹配**。

> **注**：第 3 点是本协议的一个已知缺陷。训练时只用 `gold_blocks[0]`
> 作为正类，而评测按集合 F1 计分。这会让训练信号弱于评测要求。
> 协议已冻结，**本轮不做修改**；应在下一轮协议中修正。

### 6.1 量化的不匹配

| 项 | 值 |
|---|---|
| 测试集 gold 块总数 | **374** |
| 每条训练信号覆盖的块数 | **1** |
| 集合大小为 3 的测试条目 | 32 / 171 |

**训练目标只奖励找到 1 个块，评测要求找全 2–3 个。**

这意味着：即使 loss 正常下降，模型也没有被训练去寻找完整集合。
**loss 停在 ln(12)=2.48 附近，与此一致。**

### 6.2 因此九次运行的结论边界（事先声明）

**本轮九次运行能回答的问题**：

| 问题 | 能否回答 |
|---|---|
| 在这个具体训练目标下，carried 是否优于 static/shuffled | ✅ 能 |
| 该差异是否跨划分一致 | ✅ 能 |
| **JM-R 机制在跨块组合任务上是否有效** | ❌ **不能完整回答** |

若结果为"未达标准"，**不能归因于记忆机制**——
训练目标本身与评测不一致，模型可能只是在学一个较弱的目标。

**下一轮协议必须修正**：训练目标应与评测一致
（例如多标签 BCE，或对集合内所有块都给正信号）。
