# Jaume 上下文长度实测（2026-11-10）

## 0. 先修了一个前提问题

350M 基座的 checkpoint **不含 lm_head**（MLM 预训练产物），
所以"上下文长度"此前无法用 PPL 测量。本轮先补了 causal 继续训练：

- 目标：next-token prediction
- 长度课程：256 → 1024 → 2048 → 4096
- 2000 步，lr 1e-4，头与 embedding 权重绑定
- loss 轨迹：67.5 (step 50) → 11.8 (step 2000)，**下降 82%**

## 1. 测法

"同一窗口、增长前缀"：对每个前缀长度 L，都在**最后 128 个 token**
上算 loss。这样比较的是"更多前文是否有帮助"，不受各位置难度差异影响。

## 2. 结果

| prefix 长度 | window loss | 说明 |
|---|---|---|
| 256 | 16.40 | |
| 512 | 16.50 | |
| 1024 | 16.86 | |
| 2048 | 15.73 | |
| **4096** | **15.60** | 最低 |

**delta = -0.80**：前缀从 256 增到 4096，窗口 loss 不升反降。

## 3. 结论

**RoPE 在 4096 上没有外推崩溃。** 这是本轮最重要的一条：

- 位置编码本身是健康的（theta=1e6，4096 远在安全范围内）
- 模型能吃下 4K 上下文而不退化
- 8192 未测（训练时因显存排除），但按 theta=1e6 的设计应该也没问题

## 4. 必须诚实标注的限制

**loss 的绝对值（16）很高，说明模型远未收敛。** 2000 步对 350M 只是热身：

- 正常收敛的 LM 在同语料上 loss 应在 3-8
- 当前 loss 16 意味着生成质量很差
- **PPL 曲线的"形状"可信（不随长度退化），"绝对水平"不可信（欠训练）**

要得到有意义的绝对 PPL，需要至少 20-50k 步（约 5-12 小时）。
本轮的目标是验证"位置编码是否外推健康"，这个目标已经达成。

## 5. 对 Jev 的指导

1. **RoPE theta=1e6 + 4096 训练是安全的**，可以直接作为 Jev 的起点；
2. **Jev 的预训练步数要按"收敛"而不是"能跑"来定**——
   这次 2000 步的教训是：loss 降 82% 看起来很好，但绝对值仍不可用；
3. 训练长度课程（256→4096）有效，loss 全程单调下降，可以沿用；
4. 若要验证 8192+，需要先在训练里覆盖该长度（当前受显存限制）。
