# E1–E3 任务必要性审计：Qasper 证据块任务是否真的需要跨块记忆

> 日期：2026-10-18
> 脚本：`scripts/audit_task_necessity.py`
> **只读审计：未训练、未改架构、未覆盖 checkpoint。**
> 检查点：`output/mem/R1-smoke-additive`（1 epoch，≤12 块）
> 测试集：122 条，随机基线 **0.0847**

## 0. 先修正一处表述（采纳评审）

上一版写"记忆对损失没有帮助"，过强。已改为：

> **在当前 checkpoint、当前训练阶段（1 epoch）与当前评测设置下，
> 没有测出可重复的记忆收益。**

1 轮训练不足以区分"机制不适用"与"尚未充分训练"。

## 1. E1 距离分层：**分层失效，证据力弱**

| 分层 | n | reset | concat | carried | carried−reset |
|---|---|---|---|---|---|
| d=1–3 | **3** | （太少） | | | |
| d=4–7 | **6** | 0.000 | 0.000 | 0.000 | +0.000 |
| d≥8 | **112** | 0.116 | 0.116 | 0.045 | −0.071 |

**问题：122 条中 112 条（92%）集中在 d≥8，其余两层各只有 3–6 条。**

因此"reset 随距离是否退化"**无法被检验**。脚本输出的
"reset does NOT degrade" 只反映了 d=4-7 → d≥8 的变化，
而这两层样本量都极小，**不能作为结论**。

**E1 判定：不可用（分层失衡）。**

## 2. E2 证据块反事实：**模型基本不看证据**

用另一篇论文的块替换真实的证据块，观察预测是否改变：

```
changed prediction in 23 / 120 = 0.192
```

**只有 19.2% 的预测发生变化。**

如果模型真的依赖证据内容，替换证据块应当大幅改变预测
（理想情况下 > 0.8）。实测 0.192 说明
**模型对"证据块里写了什么"基本不敏感**。

**E2 判定：模型不是证据敏感的 → 可能存在位置或其他捷径。**

## 3. E3 跨块必要性：**决定性证据**

### 3.1 证据块 vs 同论文干扰块（二选一）

```
accuracy = 0.525   （随机 = 0.500）
```

**模型几乎无法区分"含答案的块"和"同一篇论文里随便挑的块"。**

这比整体准确率更严格：整体是 12 选 1（随机 0.085），
而二选一剥离了位置与候选数的影响。**0.525 说明内容本身没有被利用。**

> **修正记录**：该检查最初实现为"只给证据块，看 argmax 是否为 0"，
> 得到 1.000。这是**循环论证**（单个块的 argmax 必然是 0），
> 已删除并改为上述二选一设计。

### 3.2 完整文档下的三种条件

| 条件 | 准确率 |
|---|---|
| reset（逐块独立编码后用状态？见注） | 0.107 |
| carried | 0.049 |
| 打乱块顺序 | 0.131 |

> 注：`reset` 在本框架中等同于"不传状态"，与 `concat`（独立编码）数值相同，
> 这一点在 E1 表中可见（0.116 = 0.116）。

**打乱顺序（0.131）反而高于原顺序（0.049–0.107）**，
进一步说明模型没有利用顺序信息，也没有利用跨块关系。

## 4. 三条判据汇总

| 判据 | 结果 | 说明 |
|---|---|---|
| reset 随距离退化 | **NO**（不可用） | 分层失衡，无法检验 |
| 模型对证据敏感 | **NO**（0.192） | 替换证据块几乎不改变预测 |
| carried > reset | **NO**（0.049 vs 0.107） | 记忆为负收益 |
| **证据块 vs 干扰块** | **0.525** | **内容未被利用** |

## 5. 结论：按评审的预注册分支

| 分支 | 是否命中 |
|---|---|
| 独立编码基线已解决任务 → 暂停长训，换任务 | ⚠️ 部分 |
| 任务需要跨块记忆但模型没利用 → 训练 5–10 epoch | ❌ 证据不支持 |
| 证据块移除后预测几乎不变 → 检查数据/评测实现 | ✅ **命中** |

**规则原文**：

> 如果证据块移除后预测几乎不变：优先检查数据构造、标签映射、证据定位和评测实现，
> 不继续改模型。

实测变化率 **0.192**（远低于"几乎不变"之外的合理范围），
且二选一只有 0.525。**因此按规则应检查数据与评测实现，而不是训练更久或改 gate。**

## 6. 但在归咎于数据之前，有一个更重要的观察

**所有条件（reset 0.107、carried 0.049、shuffle 0.131）都落在随机附近**
（随机 0.085），且 **carried 低于 reset**。

这意味着**模型根本没有学会这个任务**——
不是"记忆机制无效"，而是**任务本身在 1 epoch 下没学会**。

因此"证据块移除后预测不变"有两种解释，**当前无法区分**：

1. **数据/评测实现有问题**（证据定位错误、块与问题不匹配）；
2. **模型没学会任务**（1 epoch，loss 停在 ln(块数)）。

**Q1 已排除明显的数据泄漏**（论文级划分 0/0/0、答案不在问题中、
词面基线 0.0565 vs 随机 0.0389），因此 (2) 的可能性不低。

## 7. 数据一致性检查（已执行，否定了"数据有问题"）

脚本：`scripts/check_evidence_lexical.py`（纯 CPU，无需训练）

在**同一批 122 条、"证据块 vs 同论文干扰块"二选一**上，用无训练的检索方法评测：

| 方法 | 二选一准确率 | 说明 |
|---|---|---|
| 随机 | 0.500 | |
| **训练过的 350M 模型（carried）** | **0.525** | 几乎等于随机 |
| 词面重叠（无模型） | 0.607 | |
| **BM25（无模型）** | **0.680** | **比模型高 0.155** |

全文档排序 MRR：

| 方法 | MRR |
|---|---|
| 模型 carried | ~0.27 |
| **BM25** | **0.437** |

### 7.1 这组结果说明什么

1. **数据构造是有效的**：证据块与问题之间确实存在可检测的关联（BM25 0.68）。
   "证据定位错误"这一解释**被排除**；
2. **模型的表现低于一个零训练的 BM25**：说明当前 checkpoint 根本没学到
   "把问题匹配到相关块"这件事；
3. 因此按评审的预注册分支，"优先检查数据构造"这一支**已排除**，
   剩下的是**训练不足**。

### 7.2 但还有一层更重要的含义

**BM25 在没有任何跨块状态的情况下达到 0.68。**
这说明**"证据块选择"本质上是一个检索/匹配任务**，
单块内容即可判定，不需要跨块信息整合。

因此即使把模型训练到 BM25 的水平，也**不能证明跨块记忆有价值**——
它只会证明模型学会了检索。

## 8. 结论与建议

### 8.1 已确立

| 主张 | 判定 |
|---|---|
| Qasper 证据块任务需要跨块记忆 | ❌ **无证据支持** |
| 数据构造有误 | ❌ **已排除**（BM25 0.68） |
| 模型学会了任务 | ❌ **没有**（0.525 < BM25 0.68） |
| 改 gate 能解决 | ❌ **已否定**（判别实验） |

### 8.2 按评审的分支

评审给出的第一条：

> **如果独立编码基线已经解决任务：暂停长训。
> 先更换真正要求跨块信息整合的任务，避免把不必要的记忆能力当作训练目标。**

**当前证据最接近这一条**，但不是"独立编码基线已解决"，
而是**"零训练的检索基线已接近解决，且不需要跨块状态"**。

### 8.3 因此建议

**不建议批准 5–10 epoch 的长训**，理由：

1. 训练更久最多让模型达到 BM25 的水平（检索），
   而这**不能验证记忆机制**；
2. 任务性质是"问题↔单块匹配"，跨块状态在此任务上没有发挥空间；
3. 之前的合成任务（需要两块组合）才是更贴合机制的实验，
   它在 2 块时已给出正结果。

**建议改为**：设计一个**必须整合多个块**的任务
（例如答案需要跨 2 个以上块的组合推理），
而不是继续在证据块选择上调模型。

## 9. 局限

1. 单一 checkpoint、1 epoch；
2. E1 分层严重失衡（d≥8 占 92%）；
3. 测试集 122 条，0.05 量级差异不显著；
4. BM25 是强基线，但"BM25 好"不等于"任务简单到无需记忆"——
   只是说明该任务**可以用检索方式完成**。

## 11. 跨块组合子集：构造与准入（已完成，只读 + 零训练）

### 11.1 构造（`scripts/make_qasper_composition.py`）

从 Qasper 全量（train+dev，888+368 篇）按预注册门槛筛选：

| 筛除原因 | 数量 | 对应评审的担忧 |
|---|---|---|
| 只有单条证据 | 2281 | — |
| **证据全落在同一块** | **240** | ✅ **"证据多 ≠ 需要跨块"** |
| **证据冗余（Jaccard≥0.5）** | **31** | ✅ **"多条引文只是重复"** |
| **BM25 单块即可胜出** | **289** | ✅ 单块足够 |
| 证据块数 >3 | 165 | 控制难度 |
| **保留** | **592** | |

**评审预判的两类伪多证据，实测分别为 240 和 31 条，被正确剔除。**

最终划分（按论文）：train 349 / val 119 / **test 124**，
论文重叠 **0 / 0 / 0**。证据块数：2 块 95 条、3 块 29 条。

### 11.2 任务形式

**答案块集合选择**（multi-select）：
给定问题，选出**共同**承载证据的块集合。
指标为集合级 precision / recall / F1，不是 top-1。

选择这种形式的原因：350M 编码器无法自由生成，
但"同时保留多个块的信息并选出正确集合"正是待检验的组合能力。

### 11.3 零训练基线（`scripts/check_composition_baselines.py`）

| 基线 | precision | recall | F1 |
|---|---|---|---|
| B1 BM25 top-k | 0.140 | 0.140 | 0.140 |
| B2 词面重叠 top-k | 0.220 | 0.220 | 0.220 |
| B3 随机 k 块 | 0.172 | 0.172 | 0.172 |
| **B4 单个最佳块** | **0.000** | 0.000 | **0.000** |

**BM25 精确集合命中率：0 / 124 = 0.000**

**最强零训练基线 F1 仅 0.22，低于"0.45 可用"的门槛。**

### 11.4 一个必须解释的异常

**随机基线 (0.172) 高于 BM25 (0.140)**，这不合理。

原因：构造阶段已剔除"BM25 单块能赢"的 289 条，
剩下的样本对 BM25 天然不友好。**这是选择偏差**，不是任务更难。

**但它反而证实了任务的性质**：

| 观测 | 解释 |
|---|---|
| 89/124 条样本，问题与所有块的词面重叠 < 0.10 | Qasper 的问题是**抽象提问**，证据是**具体发现** |
| BM25 完全失效（精确命中 0/124） | 无法靠词面定位证据 |
| 单个最佳块 F1 = 0.000 | **单块永远不足以覆盖答案集合** |

例：
```
问题：How do the various social phenomena examined manifest in
      different types of communities?
证据：we find that dynamic communities, such as seahawks or starcraft,
      have substantially higher rates of monthly user retention...
```

**问题与证据几乎无共同词汇**——这就是为什么词面方法失效。
