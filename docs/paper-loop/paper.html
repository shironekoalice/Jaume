Depth Saturation Predicts When Looping Cannot Help: A Controlled Negative Result on Looped Transformers at 350M

Kru Zeppesey
Jaume Project · ModelScope: LightNeko/Jaume
Abstract. Looped and recurrent transformers are claimed to buy reasoning depth without buying parameters: apply the same block $ times and get \times$ the effective depth. We test this claim at 350M parameters on a single Ascend 910B3 and find it does not hold here, for a structural reason rather than a tuning failure. Our central contribution is a cheap depth-saturation criterion: train plain 8L and 16L models on the target task before trying a loop. If 16L does not clearly beat 8L, the task is already computed in a single forward pass and looping can only repeat it. We validate the criterion across eight task structures and four modalities, including a task that is genuinely learnable (8-digit addition, 0.89 exact match) and genuinely serial (carry propagation). In every case 8 layers saturate. We further give a mechanism: inter-round updates form a contraction with geometric decay ratio $\approx 0.6$, so extra rounds converge to a fixed point rather than reasoning further.

1. Introduction

A looped transformer applies the same block repeatedly, so parameters stay fixed while effective depth grows. Recent work reports gains: LoopMTP, ECHO, LLA. These are positive results from large models trained for long. The natural question is when the mechanism cannot work at all.

We ran a pre-registered equal-compute comparison at 350M and it failed: the loop configuration matched for wall-clock was 0.99 nats worse than plain training. Rather than tune further, we measured why, and the measurement turned into a predictor.

Contributions.

  • A cheap pre-flight criterion: depth-scan the task first (§4).
  • Eight task structures and four modalities, all consistent (§6).
  • A mechanism: rounds contract geometrically, ratio $\approx 0.6$ (§5).
  • The distinction between not learnable and not depth-limited, which a naive reading of the parity result would conflate (§7).

2. Setup

All runs use Jaume-Causal, a 350M MoE transformer (16 layers, =512$, 4 experts, top-2) on one Ascend 910B3 with 61 GiB HBM. Training is AdamW, bf16 autocast, learning rate \times10^{-4}$ with cosine decay. Every comparison uses identical data, seed, and step budget unless stated.

Loop implementation. The looped variant re-applies the full stack $ times with per-round gating, following the standard “full loop, repeat position” form. Latent-alignment supervision is available as an ablation.

4. Mechanism: rounds contract

We probed the loop-4 checkpoint at inference with =1\ldots8$ (same weights, no retraining). Two measurements:

Inter-round relative distance.

441T{=}8:\; 0.552 \to 0.363 \to 0.213 \to 0.137 \to 0.097 \to 0.074 \to 0.060441

Monotone geometric decay, ratio $\approx 0.6$. Rounds 1–2 change the representation by 55% and 36%; round 7→8 changes it by 6%.

Principal-subspace overlap.

441T{=}8:\; 0.681,\ 0.848,\ 0.945,\ 0.973,\ 0.982,\ 0.993,\ 0.991441

Overlap saturates near 0.99. All 512 dimensions are “moving” (dim-var ratio $=1.0$): the loop is not splitting labour between accumulating stable facts and advancing reasoning. It is making decaying updates of the same kind.

Reading. The loop is approximately a contraction: each round shrinks the update by a constant factor and converges to a fixed point. Extra rounds are not thinking, they are converging. This explains the equal-compute loss and also reinterprets “latent overthinking”: the fixed point is already reached.

5. The depth-saturation criterion

If rounds are extra depth, a loop can only help when depth helps. So measure that directly, before spending compute on the loop:

Train plain 8L and 16L models on the target task, identical data and steps.

  • 16L beats 8L by $>0.01$ (nats or task metric): the task is depth-limited; a loop has room.
  • 16L $\approx$ 8L: the task is computed in one pass; looping is structurally guaranteed to lose to more data at equal compute.

The scan costs about 0.1 GPU-hour per depth on this hardware, under 0.3 hours total, versus 10+ hours for a full loop comparison.

Depth scan across eight task structures. The last row is the strictest: genuinely learnable, genuinely serial (carry propagation), strict exact-match scoring. 16L gains only 0.0067 over 8L while costing .8\times$ the time.

Why the addition row matters. Earlier rows can be explained away. Chain lookup and constraint paths are computed by transitive closure; sequence reduction and counting are parallel aggregation. But 8-digit addition is the task the loop literature itself uses to argue for depth: the carry into column $ depends on the carry out of column -1$, and the answer digits appear nowhere in the input. It is learnable (0.89 exact match) and strict (one wrong digit is zero). Yet 8 layers saturate: 0.8900 vs 0.8967.

The mechanism is that attention parallelises the carry. Whether column $ produces a carry is a local function of the two input digits; a model can read all columns at once and compute the carry propagation as a closed-form function of the inputs, without ever passing state column by column.

7. Not learnable is not the same as not depth-limited

Parity is the standard hard task for shallow models, so it looks like the ideal stress test. It is not, and the distinction matters.

At 8, 16 and 32 layers parity stays at chance (0.50–0.58) with cross-entropy not decreasing. This is optimisation invisibility, not a depth limit: the gradient signal is too weak for the function to be learned at any depth. Reading it as “not enough depth” would produce exactly the wrong conclusion.

A usable criterion therefore has two clauses, not one: (a) the task must be learnable, (b) 16L must beat 8L. Only tasks satisfying both are candidates for looping. The addition experiment is the one that satisfies both, and it still saturates.

8. Implications

  1. Screen before you loop. A 0.3-hour depth scan can rule out a direction that would otherwise cost 10+ hours.
  2. Scaling this model up will not rescue looping. If 8 layers already saturate, more layers saturate sooner, and loops have less to add, not more.
  3. Look for tasks where attention cannot collapse the serial structure — incompressible state that must be carried, not recomputed: game-tree search with bounds, or an interactive environment with memory. These remain open.

9. Limitations

One model size (350M), one architecture family, largely synthetic tasks. The criterion is validated as a negative screen: when 8L saturates, the loop is ruled out. We do not claim the converse — a depth-limited task is necessary for looping to help, not sufficient. The positive direction (what happens when 16L does beat 8L) is untested here because we could not construct such a task at this scale.

10. Conclusion

At 350M, on every task structure and modality we could construct, eight layers suffice. Where that holds, looping cannot pay, and a cheap depth scan says so in advance. The transferable result is the scan itself: measure whether depth helps before paying for a loop.
