# R1 分阶段实验：状态更新修复（诊断轮）

> 日期：2026-10-18
> 脚本：`scripts/train_r1.py`、`jaume/modeling/memory.py`（新增 `state_update` 开关）
> 数据：`data/qasper_blocks/`（Qasper，12 块上限）
> **本轮为单 epoch 诊断轮，不是最终判定。**

## 1. 先修正的措辞（采纳评审意见）

上一版文档中的三处过度推断已收回：

| 原表述 | 修正后 |
|---|---|
| "累积项主导导致坍缩" | **候选解释之一**，未经干预验证 |
| "只有 ≥8 块才会出现" | **未验证**，只测了 2 块与 12 块 |
| "归一化可修复" | ❌ **被本轮结果否定** |

## 2. 三种状态更新模式（已实现，默认不变）

`jaume/modeling/memory.py` 的 `slot_pass` 新增 `state_update` 配置：

```python
additive  slots = slots + read                    # 原始行为（默认）
norm      slots = LayerNorm(slots + read)         # R1a
bounded   g = sigmoid(W[slots; read])
          slots = LayerNorm((1-g)*slots + g*read) # R1b
```

**默认 `additive`，旧 checkpoint 完全不受影响**（已验证 309/318 张量复用）。
`bounded` 的 gate 初始化为零 → 起始 g=0.5，不预设饱和。

**为什么用 LayerNorm 而不是 L2 规范化**：评审指出 L2 只约束尺度、不改变方向；
LayerNorm 逐 slot 归一化，至少让状态分布有界。

## 3. 单 epoch 诊断结果

同一数据划分、同一预算（402 训练样本，12 块，bps=4，1 epoch）：

| 模式 | 块间余弦 | 块表示 std | 状态范数 | val acc@1 | **TEST carried** | TEST reset | TEST shuffled |
|---|---|---|---|---|---|---|---|
| **additive（原版）** | 0.9895 | 0.0037 | **37.2 → 205.3** | 0.0750 | **0.0492** | 0.1066 | 0.0656 |
| **R1a norm** | 0.9914 | 0.0031 | **64.0 → 63.9** | **0.1500** | **0.1230** | 0.1393 | 0.0492 |
| **R1b bounded** | 0.9901 | 0.0035 | **64.0 → 64.0** | 0.1250 | **0.0984** | 0.0984 | 0.1148 |

（test n=122，随机基线约 0.082）

## 4. 逐层判定（按评审的四层标准）

### 4.1 表示层：**部分改善，坍缩未解决**

| 目标 | 结果 |
|---|---|
| 状态范数不再失控 | ✅ **解决**：205.3 → 64.0（R1a/R1b） |
| 非证据块与证据块的状态可区分 | ❌ **未解决**：余弦仍 0.9901–0.9914 |

**这是本轮最重要的发现之一：范数失控与表示坍缩是两个独立问题。**
归一化修好了前者，对后者无效——正如评审所预测的
"归一化只约束尺度，不改变方向"。

### 4.2 任务层：**有改善**

| 模式 | val acc@1 | TEST carried acc@1 |
|---|---|---|
| additive | 0.0750 | 0.0492 |
| **R1a** | **0.1500** | **0.1230** |
| R1b | 0.1250 | 0.0984 |

R1a 相对原版提升 **2.5 倍**（0.049 → 0.123），超过随机（0.082）。
**但要谨慎**：单 epoch、单种子，且 R1a 的 `reset` 也更高（0.139），
说明部分提升可能来自整体训练稳定性，不全是状态传递。

### 4.3 机制层：**未通过**

| 模式 | carried | reset | carried−reset |
|---|---|---|---|
| additive | 0.0492 | 0.1066 | **−0.057** |
| R1a | 0.1230 | 0.1393 | **−0.016** |
| R1b | 0.0984 | 0.0984 | **0.000** |

**三种模式下 `carried` 都不优于 `reset`。**

- additive：carried 比 reset 差一半（负收益）
- R1a：差距缩小到 −0.016，仍未转正
- R1b：完全相等

**按预注册判据（carried > reset 且 > shuffled），机制层不通过。**

### 4.4 泛化层：**未做**

单数据划分、单种子。多种子 ≠ 多数据集，需换论文级划分重测。

## 5. 结论（严格）

| 主张 | 判定 |
|---|---|
| 状态范数失控是真实问题 | ✅ **成立**（37→205 直接测量） |
| 归一化可修复范数失控 | ✅ **成立**（205→64） |
| 归一化可修复表示坍缩 | ❌ **不成立**（余弦 0.99 不变） |
| 有界更新改善任务表现 | ⚠️ **弱证据**（单 epoch，0.049→0.098） |
| 机制层通过（carried > reset） | ❌ **不通过** |

**不能说"R1b 有效"。**
准确表述：**R1b 把范数失控修好了，并让任务表现从"低于随机"回到"接近随机"，
但没有让状态传递产生正收益。**

## 6. 按评审的下一步：计算图与梯度诊断（已执行）

评审指定："若两者都失败，就暂停这条更新路线，检查 `slot_pass` 的实际计算图与梯度，
而不是继续堆归一化技巧。"

`scripts/diagnose_state_grad.py` 的三个直接测量：

### D1 状态每步移动多少

| 块 | \|Δ\|/\|s_prev\| | cos(s_{i−1}, s_i) |
|---|---|---|
| 1 | **0.3176** | 0.9770 |
| 3 | 0.2219 | 0.9934 |
| 5 | 0.1581 | 0.9970 |
| 7 | 0.1261 | 0.9978 |
| 9 | 0.1024 | 0.9988 |
| **11** | **0.0979** | **0.9992** |

**相对变化量从 0.32 单调衰减到 0.098，余弦趋近 1。**

这是**累积稀释的直接测量证据**——
新块对状态的相对贡献随块数增加而递减，与"累积项主导"的假设一致。

### D2 梯度是否回传

```
backbone grad norm = 1298.36
pooling  grad norm =  178.80
```

**梯度不为零，回传正常。**
**"梯度断裂"这一解释被排除。**

### D3 交叉注意力读出是否有区分度

```
read-out 块间平均余弦 = 0.7651
read-out std          = 0.0206
```

对比：**状态**的块间余弦是 **0.99**。

### 6.1 这组诊断的结论（本轮最关键的发现）

| 环节 | 块间余弦 | 判断 |
|---|---|---|
| 交叉注意力**读出** `read_i` | **0.7651** | ✅ 有区分度 |
| 状态**更新后** `state_i` | **0.9901** | ❌ 差异被抹掉 |

**坍缩发生在状态更新步骤，不在读出步骤。**

这意味着：

1. **读出机制本身没问题**——注意力确实对不同的块读出了不同的内容；
2. **更新步骤把差异抹掉了**——`state_i = state_{i-1} + read_i` 中，
   `read_i` 的差异相对于已累积的 `state_{i-1}` 太小（D1 显示 0.098）；
3. **梯度通路正常**（D2），所以不是优化问题。

### 6.2 因此 R1a/R1b 失败的原因清楚了

两种归一化都作用在**更新之后**（`norm(slots + read)` 或 `norm((1-g)s + g·read)`）：

- LayerNorm 逐 slot 归一化，**把不同块的状态拉向同一个分布位置**；
- 这正是实测到的现象：归一化后余弦**升高**（0.9509 → 0.9807 / 0.9779）；
- 没有改变"`read_i` 相对贡献过小"这个根因。

**结论：问题在更新的权重分配，不在输出的尺度或方向。**

## 7. 下一步的唯一有依据方向（未实施）

既然读出有区分度（0.765）而更新后没有（0.99），
正确的做法是**增大新块在状态中的权重**，而不是归一化。

具体：`g_i` 不应是一个全局标量，而应**由当前块与历史的相关性决定**——
当新块带来新信息时，g 应接近 1（覆盖）；当新块重复历史时，g 应接近 0（保留）。

R1b 的 gate 正是这个结构，但它初始化为 g=0.5 且**与块内容的差异度无关**，
所以学不到"何时该覆盖"。

**建议的下一步不是再加变体，而是先做一个更基础的检查**：
测 `read_i` 与 `read_{i-1}` 的差异度，与 `g` 的实际取值是否相关。
若不相关，说明 gate 没有接上判别信息，需改的是 gate 的输入。

**这一项尚未执行，需评审确认后再做。**

## 7. 诚实标注的局限

1. **单 epoch、单种子**，所有任务层数字都不能作为最终结论；
2. R1b 训练异常慢（2237s vs R1a 377s），**原因未查明**，
   可能影响公平比较（同样的 epoch 数但内部状态不同）；
3. test n=122，随机基线 0.082，0.05 量级的差异不显著；
4. **表示坍缩的因果仍未确定**——三种方式都坍缩，说明问题可能在
   `read` 或 `cross_attend`，而不在 `state_update`。
