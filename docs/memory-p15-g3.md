# P1.5 / G3 结果：跨输入记忆的判决性实验

> 日期：2026-10-17
> 任务生成：`scripts/make_crossblock_v3.py`
> 关卡 G2：`scripts/g2_concat_gate.py`、`scripts/g3_350m_concat.py`
> 记忆比较 G3：`scripts/g3_memory.py`
> 数据：`data/synth_v3/`（4000/1000/1000）
> **停止条件已按评审意见事先固定，未事后调整。**

## 0. 结论

**在一个经过完整验证的实验台上，跨输入记忆状态没有产生任何收益。**

```
concat   0.476   ← 两块一起给，能学会
reset    0.158   ← 只能看块 A
carried  0.158   ← 传状态，毫无提升
shuffled 0.154   ← 喂错状态，和喂对的一样
```

随机基线 **0.167**。

## 1. 关卡 G1：任务没有捷径 ✅

| 划分 | n | 随机 | 词面泄漏 | 词面上限 | Oracle | 答案唯一性 |
|---|---|---|---|---|---|---|
| train | 4000 | 0.167 | **0.000** | 0.249 | **1.000** | ✅ 100% |
| dev | 1000 | 0.167 | **0.000** | 0.250 | **1.000** | ✅ 100% |
| test | 1000 | 0.167 | **0.000** | 0.242 | **1.000** | ✅ 100% |

任务形式：

```
块 A：Protocol DORULEIORUM retains audit logs for 43 days.
       Protocol LOMEFIEOMIR retains audit logs for 79 days.
块 B：Adopt the protocol that carries the smaller value.
查询：Name the protocol in force.        ← 不含任何协议名
答案：DORULEIORUM                        ← 唯一（43 < 79）
```

**为什么这个设计修掉了之前的缺陷**：

- 块 B **不含任何暗示形容词**（不说 "stricter"/"safer"），只给**比较方向**（smaller/larger）；
- 方向**逐条 50/50 平衡**，所以"总选第一个"或"总选小数字"都不能作弊；
- 答案由数值比较**唯一确定**，由 oracle 逐条验证（1000/1000）；
- 协议名是无意义伪词，跨划分不重复。

> **诚实标注**：词面上限 0.242–0.250 偏高（刚好卡在阈值边缘），
> 原因是 6 个候选中必有 2 个出现在块 A 里，这是这类任务的固有下限。
> 但它**低于随机基线所对应的"候选内命中率"**，且 oracle 独立验证了答案唯一性，
> 因此不构成捷径。

## 2. 关卡 G2：无记忆模型能学会 ✅

### 2.1 从零训练的词袋模型（3 种子）

| 种子 | concat 准确率 |
|---|---|
| 0 | 0.452 |
| 1 | 0.469 |
| 2 | 0.440 |

门槛 = 随机 + 0.10 = 0.267。**3/3 通过**，平均 0.454（2.7 倍随机）。

### 2.2 Jaume-350M 编码器

| 条件 | 测试准确率 |
|---|---|
| concat（350M，2 epoch） | **0.471** |

loss 0.4885 → 0.0365。**PASS**。

**这是本次研究第一次证明：任务无捷径、答案唯一，且模型能学会它。**

### 2.3 一个必须记录的 bug

首次跑 G2 得到 **0.001**（远低于随机）。我按停止条件准备终止，
但先排查实现，发现两处 bug：

1. **词表未覆盖测试集**：伪词名字跨划分不重复，
   train-only 词表把测试集所有候选名都映射到 padding id → 候选无法区分；
2. **候选编码分布不匹配**：用裸候选名评分，而训练目标是完整答案串。

修复后从 0.001 → 0.454。

**教训：任何触发停止条件的异常结果，必须先排除实现错误，
否则会用一个 bug 结束整个研究方向。**

## 3. 关卡 G3：记忆比较（判决性）

固定任务、数据、训练协议（1 epoch，lr 2e-4，bs 32，B5 权重），对比四个条件：

| 条件 | 含义 | 准确率 |
|---|---|---|
| **concat** | 两块拼一起一次编码 | **0.476** |
| **reset** | 逐块，不传状态 | **0.158** |
| **carried** | 逐块，传状态 | **0.158** |
| **shuffled** | 逐块，传**别的条目**的状态 | **0.154** |

随机 0.167。

### 3.1 判据（事先固定）

```
记忆有效  <=>  carried > reset  且  carried > shuffled
```

- `carried > reset`：0.158 vs 0.158 → **不成立**
- `carried > shuffled`：0.158 vs 0.154 → **不成立**（打乱状态甚至略低，属噪声）

**判定：无记忆收益。**

### 3.2 为什么这一轮排除了所有替代解释

| 可能的辩驳 | 本轮证据 |
|---|---|
| 任务有捷径 | ❌ 词面泄漏 0.000；oracle 1.000；答案唯一 100% |
| 答案有歧义 | ❌ oracle 逐条验证 1000/1000 可推导 |
| 模型学不会任务 | ❌ **concat 0.476（2.7× 随机）** |
| 记忆从未训练 | ❌ 训练时状态真实传递，loss 4.09→3.83 |
| 收益来自批处理/容量 | ❌ **shuffled：喂错状态与喂对状态完全相同** |
| carried 分支有 bug | ⚠️ 已核对：二者都走 `model.encode(..., state)`，仅 state 来源不同 |

**剩余的唯一解释：跨输入状态没有向后续块传递任何可用信息。**

### 3.3 `concat` 与 `reset` 的巨大差距说明了什么

`concat` 0.476 vs `reset` 0.158 的差距（0.318）**正是块 B 的信息价值**：
不给块 B，模型完全无法作答。所以任务是**真的需要跨块信息**——
但现有的状态通路**无法承担这个传递**。

## 5. 严格的最终判定

| 主张 | 判定 |
|---|---|
| JM-R 在预注册标准下通过 | ❌ 未通过 |
| 在本实验台上记忆带来收益 | ❌ **无收益（决定性）** |
| **"跨输入记忆路线已被证伪"** | ⚠️ **不能这样断言** |

**为什么不能断言路线被证伪**：本轮只检验了**一种状态通路**
（B5 的 8 槽 recurrent + mean 池化）。结论的准确表述是：

> **在当前实现（8 槽状态 + 槽均值池化 + 门控）与当前训练目标下，
> 跨输入状态没有产生可测量的信息传递。**
> 这不排除其他状态设计（更大的状态、显式读写、注意力式记忆）可能有效。

## 6. 建议的下一步

1. **优先诊断状态通路本身**：在合成任务上，即使不做端到端训练，
   也应能验证「块 A 的信息是否进入了 state」——
   例如线性探针：用 state 预测块 A 的事实，若探针都做不到，
   说明状态容量/结构不足，而非训练问题。
2. 若线性探针能读出信息但端到端无效，则问题在**读出环节**（如何把 state 用于评分）；
   若探针也读不出，则问题在**写入环节**（state 容量不足）。
3. 在此之前不应再增加训练预算或数据规模。
