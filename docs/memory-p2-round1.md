# P2 首轮结果：在合成跨块任务上训练

> 日期：2026-10-17
> 训练：`scripts/train_memory.py`（batch 96，1 epoch，6000 对）
> 评测：`scripts/p1_acceptance.py`（1500 条测试，随机基线 0.152）
> 数据：[memory-p1-synthetic-task.md](memory-p1-synthetic-task.md)（成立性已验证）

## 1. 结果

test 划分，1500 条，平均 6.8 个候选，**随机基线 0.152**：

| 臂 | 是否训练 | indep | reset | **carried** | concat | q_only |
|---|---|---|---|---|---|---|
| **P2-B5-synth** | ✅ 是 | 0.1520 | 0.1520 | **0.1387** | 0.1467 | 0.1593 |
| **P2-B6-synth** | ✅ 是 | 0.1533 | 0.1533 | **0.1380** | 0.1587 | 0.1507 |
| B0-mean | ❌ 否 | 0.1527 | 0.1527 | 0.1527 | 0.1540 | 0.1547 |
| B3-latent | ❌ 否 | 0.1367 | 0.1367 | 0.1367 | 0.1440 | 0.1533 |

### 1.1 `carried − reset`（唯一干净的对照）

| 臂 | 差值 | 折合样本数（n=1500） |
|---|---|---|
| **P2-B5-synth** | **−0.0133** | ≈ −20 条 |
| **P2-B6-synth** | **−0.0153** | ≈ −23 条 |

**在专门训练之后，传递状态比不传递更差。**

### 1.2 全部策略都在随机水平

所有格子落在 **0.137–0.159**，随机基线 0.152。
**没有任何策略、任何臂显著超过随机。没有模型学会这个任务**——
包括专门为它训练的 B5/B6。

## 2. 为什么这个负面结果比上一轮强

上一轮的负面结果可以被多种原因解释；本轮把替罪羊逐个排除：

| 可能的解释 | 本轮状态 |
|---|---|
| "任务本身可以用捷径解" | ❌ 排除：词面上限 0.081 < 随机 0.152，单块上限 0.081 |
| "答案是主观的/不可推导" | ❌ 排除：oracle 解析器 1500/1500 = 1.000 |
| "对照实现有 bug" | ❌ 排除：B0/B3 的 indep=reset=carried 恒等保持 |
| "批量设置不同导致不可比" | ❌ 排除：全部 batch 96 + accum 1 |
| "`independent` 批处理污染" | ❌ 排除：P0 审计后已改为与 `carried` 一致的逐块路径 |
| "模型没见过这个任务" | ❌ 排除：已在 6000 对训练数据上专门训练 |

**剩下的解释**：当前状态通路的设计（8 槽 + 槽 mean 池化 + 门控）
**在真正需要跨块信息的任务上学不到有用的信息**，而且传递状态引入了噪声。

## 3. 一个重要的观察：训练没有让模型学会任何策略

如果状态机制只是"没学会做跨块"，我们仍会期待
`concat`（整段一次性编码，无需记忆）能高于随机——
因为它是纯编码能力，不依赖记忆。

实测 `concat` = 0.1467 / 0.1587，**同样在随机水平**。

这说明：**1 epoch / 6000 对的对比学习不足以让模型学到这个合成任务的"实体-属性查表"能力**，
与记忆机制无关。因此本轮的
`carried − reset < 0` **不能直接归因于记忆机制失败**——
它可能只是"模型还没学会任务"。

**这是本轮最重要的谨慎点，不可忽略。**

## 4. 因此的下一步（P2 续）

不能就此断言记忆失败。必须先确认**任务可学习**：

1. **提高任务可学习性**：
   - 训练更久（3–5 epoch）或更大数据；
   - 降低任务难度（减少干扰对数量、减少候选数）；
   - 先验证：**`concat` 策略能否显著超过随机**。
     这是任务可学习性的最直接指标——若 `concat` 做不到，
     说明瓶颈在编码/优化，而不在记忆。

2. **只有在 `concat` 明显超过随机之后**，
   才用 `carried − reset` 判定记忆机制。

3. **容量对照**：加一个与记忆臂参数量相当的 `concat` 基线，
   排除"参数多所以好"。

### 4.1 已执行的验证：5 epoch（结果见 §8）

5 epoch 训练把训练 loss 从 3.65 降到 1.27，
但**测试集所有策略仍 ≈ 随机**（0.146–0.156）。
这排除了"训练不足"，并暴露出**训练目标本身存在捷径**（见 §8）。

## 5. 结论（严格表述）

| 主张 | 是否成立 |
|---|---|
| 任务确实需要跨块信息 | ✅ 成立 |
| 答案可推导 | ✅ 成立 |
| 现有权重（未训练）不会做 | ✅ 成立 |
| **专门训练后 `carried > reset`** | ❌ **不成立**（为负） |
| **训练让模型学会了任务** | ❌ **不成立**（所有策略 ≈ 随机） |
| **"记忆机制失败"** | ⚠️ **不能断言**——任务整体未被学会 |

**本轮最有价值的产出**：建立了第一个**经过完整验证的跨块实验台**，
并给出了明确证据说明：**在确认任务可学习之前，
任何关于记忆机制成败的结论都是无效的。**

## 7. 附：本轮修掉的两个自身缺陷

1. **生成器死循环**：实体词表空间不足（双音节仅 256 个组合），
   生成 6000 条时无限循环。已改为三音节构造（6144 空间）并加尝试上限。
2. **评测慢 20 倍**：每个块单独 tokenize + batch-of-1 前向，
   1500 条 × 2 块 × 4 策略 = 12000 次微小前向。
   已改为 `precompute_chunks` 批量预编码（无状态策略从表中取），n=1500 从 24 分钟降到约 1 分钟。
   `carried` 仍为串行——这是诚实测量状态传递的必要成本。

## 8. 追加验证：5 epoch 训练（决定性）

为区分"训练不足"与"机制失败"，用同样数据训练 **5 epoch**：

| 指标 | 1 epoch | **5 epoch** |
|---|---|---|
| 训练 loss（末） | — | **3.647 → 1.271** |
| 步数 | 62 | 310 |
| 用时 | 56 s | 279 s |

**训练 loss 显著下降 → 模型确实在拟合训练数据。**

测试集（n=500，随机 0.152）：

| 臂 | indep | reset | **carried** | concat |
|---|---|---|---|---|
| P2-B6-synth-e5（5 epoch） | 0.156 | 0.156 | **0.146** | 0.156 |
| P2-B6-synth-s1（1 epoch） | 0.138 | 0.138 | 0.144 | 0.150 |

### 8.1 诊断：训练目标本身存在捷径

**训练 loss 下降，测试集完全不涨 → 过拟合到一条捷径。**

定位到捷径：训练对的构造是

```
query    = "<块B> <问题>"         例：The item under review is VEGA. What colour is called for here?
positive = 块A                     例：VEGA 使用 red 密钥。ORION 使用 blue 密钥。……
```

**块 A 里印着实体名 `VEGA`**，而 query 里也有 `VEGA`。
因此模型只要学会「把 query 中的实体名与 positive 文本做词面匹配」，
损失就会下降——**完全不需要推理出颜色**。

于是：训练 loss 降低，但模型学到的能力（匹配实体名）
**无法转化为"找到该实体的颜色并选出正确候选"**，测试分数停在随机。

### 8.2 结论修正

| 主张 | 判定 |
|---|---|
| "训练不足导致随机" | ❌ 已排除（5 epoch，loss 1.27） |
| "记忆机制失败" | ⚠️ **仍不能断言**——训练目标有捷径，模型学的是错的东西 |
| **"实验台仍不完整"** | ✅ **成立**：任务层面无捷径（词面上限 0.08），但**训练目标层面有捷径** |

**这是一个新的、可修的缺陷：任务的"前向可解性"已干净，但"训练信号"不干净。**

### 8.3 修正方向（下一轮必做）

必须让**训练目标也只能靠跨块推理**才能降低：

1. **positive 用颜色词而非整块**：
   `positive = "red"`（答案颜色），`query = "<块B> <问题>"`。
   这样词面匹配实体名**不能**降低损失，必须真的从块 A 里查出颜色。
2. **或**：把块 A 中的实体名替换为不可见于 query 的代号，
   在 query 与块 A 之间建立只有"读懂了才能连"的关系。
3. **必做对照**：修正后 **`concat` 必须显著超过随机**，
   否则训练信号仍不干净，不得进入记忆评判。
4. 加**容量匹配**的无记忆基线。

**在 §8.3 完成前，P2 的任何 `carried − reset` 数字都不能用于评判记忆机制。**
