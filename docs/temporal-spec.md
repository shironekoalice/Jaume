# Jaume-Temporal 任务定义与 PoC 方案（v0.1）

> 状态：任务定义完成，PoC 未启动。工作名称 Jaume-Temporal。
> 试验原则来自 HARNESS 执行任务书：三个模块拆开验证、先纸面后训练、首轮只做离线仿真、不连接真实执行器。

## 1. 方向定位

Jaume-Temporal 是 Jaume 系列中的时序骨架估计与控制探索线，与 Jaume-Embedding（文本语义）方向独立：不共享骨干、数据与训练管线。

外部参考：HAST-SEC v0.1（GitHub `sola1039/HAST-SEC`，非商业许可）证明"小参数量 + 闭环状态控制"在其领域内可行——其核心模型（905 参数的四阶通道自回归 + 1.5 万参数策略网络）即完成带门控的跨帧状态预测。**它只作为方向可行性旁证与设计参考**：不复制其代码、权重或素材，不将其宣称指标（约 0.8B / 2GB）当作 Jaume 的目标或承诺。

可借鉴的三个设计姿态（思想，非实现）：

1. 状态更新带**门控**（观测可信则覆盖，不可信则保持预测）与**显式 reset**（边界处清状态）；
2. 一切时序预测对比 **persistence 基线**（预测 = 上一帧/上一块），预测必须证明自己比"不动"强；
3. 元数据诚实：`validation_scope` 标明验证是否独立泛化，失败记录保留。

## 2. 任务分解（三个可独立验证的模块）

| 模块 | 输入 → 输出 | 首轮策略 |
|---|---|---|
| M1 Pose Estimation | 视频帧 → 2D/3D 关键点 | **跳过**。首轮直接从骨架序列开始，避免视觉误差与时序误差耦合 |
| M2 Temporal Representation | 规范化关节序列 → 动作/姿态/轨迹表征 | **主攻**。PoC 的核心 |
| M3 Control / Action | 时序状态 → 动作/控制量 | **只做离线仿真**。首轮目标限定为"在 M2 表征上训练一个小型动作分类/选择头" |

## 3. 决策项（T1–T8，附建议）

以下建议基于"单卡 12GB、数据零起步、先验证后扩展"的约束给出；每项都可被项目负责人否决，否决后本文更新并重算资源预估。

| 编号 | 决策项 | 建议 | 理由 |
|---|---|---|---|
| T1 | 应用目标 | **动作识别 + 短时未来姿态预测**（识别为主） | 两者共享同一数据与指标体系，是 M2 最小闭环；生成与控制依赖数据量，放二期 |
| T2 | 输入来源 | **现成骨架数据集**（不用视频） | 跳过 M1；许可干净、直接可训 |
| T3 | 骨架标准 | **NTU RGB+D 25 关节** 或 **Human3.6M 17 关节**（二选一，见 §4 数据表） | 两者均有官方 split 与成熟基线可比 |
| T4 | 帧率/时长/延迟 | 输入统一重采样到 **20 fps**；片段 2–5 秒；PoC 阶段无硬延迟门槛，只**测量并记录** | 先建立测量习惯，门槛二期定 |
| T5 | 输出形态 | 动作类别（**macro-F1**）+ 未来 0.5s/1s 关键点（**MPJPE@horizon**） | 与 T1 对应，两个指标一次训完 |
| T6 | 资源门槛 | PoC 模型 ≤ **10M 参数**、单卡 12GB 内可训；记录峰值显存/吞吐；**不预设"2GB 部署"目标** | 与 HAST-SEC 的"小而闭环"哲学对齐；2GB 门槛留给二期按精度/帧长/batch 重测 |
| T7 | 数据许可 | 仅用 §4 表中许可明确的公开数据集；不上传任何原始数据到公共仓库 | HARNESS 红线 |
| T8 | 评测协议 | 固定官方 split；动作识别报 macro-F1 + 混淆矩阵 + class-prior 基线；预测报 MPJPE/PCK@horizon 分列；≥3 seed 报 mean±std | 预注册，防事后挑指标 |

## 4. 数据选型（T7 落地）

| 数据集 | 许可 | 任务 | 规模 | 备注 |
|---|---|---|---|---|
| **NTU RGB+D 60**（骨架 .skeleton） | 研究用途免费 | 动作识别（60 类） | ~57k 序列 / 40 subject | 官方 cross-subject / cross-view split；首选 |
| **Human3.6M**（3D 关键点） | 仅研究许可（需申请） | 姿态预测 | ~3.6M 帧 | 许可申请周期长，作为备选 |
| **AMASS**（统一 SMPL 骨架） | 各子集许可不一，需逐个核对 | 姿态预测/表征 | 40+ 小时 | 覆盖广但许可核对成本高，二期 |

首轮计划：**只用 NTU RGB+D 60 的骨架模态**做动作识别 PoC；姿态预测二期再接（届时按 T3 选 Human3.6M 或 AMASS 子集）。

数据审计产出（阶段 2 交付）：`temporal_data_inventory.csv`（来源 URL、许可证文本哈希、样本数、subject 划分、帧率、关节定义、坐标单位、下载哈希）。

## 5. PoC 方案（阶段 3）

### 5.1 模型

三层递进，前一层不过关不进后一层：

| 层 | 模型 | 参数量级 | 目的 |
|---|---|---|---|
| P1 | 按-part 均值 + 线性分类（**sanity check**） | <0.1M | 数据管线与指标正确性；低于它说明代码有 bug |
| P2 | **ST-GCN**（官方实现，许可兼容） | ~3M | 成熟基线， NTU-60 上有公开参照分数 |
| P3 | **Jaume 时序头**（自研：小型骨架 transformer + 门控状态，结构呼应 M2 的记忆槽思想） | ≤10M | 本系列自己的贡献点，只有 P2 复现成功后才动 |

### 5.2 训练与评测协议

- 输入：25 关节 × 3 坐标 × 20fps × 最多 100 帧；骨骼向量归一化 + 以脊柱中心化；
- split：官方 cross-subject（训练）/ cross-view（泛化检查），test 只在方案冻结后跑一次；
- 指标：macro-F1（主）、top-1、每类 F1 + 混淆矩阵、class-prior 与随机基线、persistence 基线（对预测头）；
- 3 seed 报 mean±std；固定种子/配置/commit/权重哈希入库；
- 系统指标：吞吐、单片段延迟、峰值显存、权重体积。

### 5.3 资源预估

NTU-60 骨架模态约 4–5GB 磁盘；P2 一轮训练（cross-subject，batch 32）预估单卡 12GB 数小时级；P3 同量级。磁盘余量需 ≥15GB（数据 + checkpoint + 日志两倍冗余）。

### 5.4 Go / No-Go（预注册）

- **Go**：P2 复现到公开参照分数 ±2%（macro-F1）；P3 在同协议下 ≥ P2 且延迟/显存可接受；进二期（加姿态预测头 + 跨数据集）。
- **No-Go**：P2 无法复现（差 >2% 且排查无果）——数据或协议有问题，停下修地基；P3 不优于 P2——记录负结果，结构回炉，不追加资源。

## 7. 安全边界（全程有效）

不连接真实机器人、外骨骼、人体设备或生产执行器；不训练涉及可识别个人影像的自采数据；原始数据不上传公共仓库；所有实验在独立目录进行，不覆盖既有产物；失败与负结果如实保留。
