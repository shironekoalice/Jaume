> 日期：2026-10-17

## 0. 术语修正（采纳评审意见）

**不再把 JM-R 描述为"尚未证明能跨块传递信息"。**

当前证据允许的准确表述：

> 在合成跨块任务上，**正确的前序状态为后续预测提供了有用信息**
> （carried 0.492 vs reset 0.161 vs shuffled 0.162，3 种子）。

**不允许的表述**（尚无证据）：

- ❌ "模型学会了普适的长程记忆能力"
- ❌ "模型学会了通用的比较关系表示"
- ❌ "机制可泛化到真实文档"

## 1. 统计表述修正（采纳评审意见）

评审指出"27 倍标准差"不是严格的显著性检验。**同意，此前表述不严谨。**

三个不同的统计量被混用了：

| 量 | 含义 | 此前误用 |
|---|---|---|
| 种子间标准差 | 训练随机性带来的波动 | 被当作效应量的分母 |
| 测试样本抽样误差 | n=1000 时的二项误差（约 ±0.015） | 未单独报告 |
| 种子内配对差值 | 同一模型上 carried 与 reset 的差 | **这才是应该报告的量** |

**下一阶段必须改为**：

1. 报告**每个种子的配对差值** `carried_i − reset_i`、`carried_i − shuffled_i`；
2. 按**测试样本**估计不确定性（bootstrap 1000 次，报 95% CI）；
3. 按**训练种子**估计不确定性（给出 3 个配对差值及其范围）；
4. 不做跨任务比较（合成任务 49.2% 与 SciFact 准确率不可比）。

## 2. 只读代码审查结果

审查文件：`scripts/train_plan1.py`、`scripts/eval_plan1.py`、`scripts/check_plan1_data.py`。

### 2.1 四条件的信息流（现状）

| 臂 | 第一步 | 第二步 | 归一化 |
|---|---|---|---|
| `carried` | `encode(A, None)` → `s_A` | `encode(B, s_A)` | projection + L2 |
| `reset` | `encode(A, None)` → `s_A` | `encode(B, None)` | projection + L2 |
| `shuffled` | 同上，但 `s_A` 按固定种子打乱 | `encode(B, s_A_perm)` | projection + L2 |
| `concat` | `encode(A, None)` → `a_repr` | `encode(B, None)` → `b_repr` | 两者**相加**后 L2 |

### 2.2 发现 1（已实证）：`concat` 原来不是公平基线，且修正后结论需下调

**问题**：`carried` 的第二步是 `encode(B, s_A)`——模型对 (B, 状态) 做了完整前向；
而原 `concat` 只是 `a_repr + b_repr` 两个**独立嵌入相加**，缺少第二步处理。

**已实测**（`scripts/eval_concat_fair.py`，无需重训）：

| 条件 | 均值 | 标准差 | 每种子 |
|---|---|---|---|
| `carried` | **0.492** | 0.012 | 0.501 / 0.496 / 0.479 |
| `reset` | 0.161 | 0.003 | 0.161 / 0.163 / 0.158 |
| `shuffled` | 0.162 | 0.018 | 0.170 / 0.175 / 0.141 |
| `concat_sum`（原，不公平） | 0.461 | 0.006 | 0.457 / 0.468 / 0.458 |
| **`concat_full`（公平：两块拼一次编码）** | **0.491** | 0.007 | 0.499 / 0.486 / 0.488 |

**配对差值（按种子）**：

| 种子 | carried−reset | carried−shuffled | **carried−concat_full** |
|---|---|---|---|
| 0 | +0.340 | +0.331 | **+0.002** |
| 1 | +0.333 | +0.321 | **+0.010** |
| 2 | +0.321 | +0.338 | **−0.009** |

### 2.3 因此必须下调的结论

**上一轮报告中的这句话作废**：

> ❌ "carried (0.492) 高于 concat (0.461)：状态传递不仅可行，
> 甚至优于把两块直接拼接"

该比较用的是不公平基线。修正后：

> ✅ **carried (0.492) 与公平 concat (0.491) 无差异**
> （配对差值 +0.002 / +0.010 / −0.009，均在噪声内）。

**准确表述**：

| 主张 | 判定 |
|---|---|
| 正确的前序状态为后续预测提供有用信息 | ✅ **成立**（carried−reset 三种子 +0.32~+0.34） |
| 收益来自正确状态而非通用偏置 | ✅ **成立**（shuffled ≈ reset） |
| **状态传递优于直接拼接全文** | ❌ **不成立**（差值 ≈0） |

**这直接影响 SciFact 规划**：
如果记忆的效用**等价于把文本拼起来**，那么在真实文档上，
它的价值只能是"突破上下文长度限制"而非"更好的理解"。
这一点必须在 SciFact 实验中明确检验——
即当摘要长到**无法一次性拼接**时，carried 是否仍能保持性能。

### 2.4 发现 2：`reset` 与 `shuffled` 的差异已足够小

`reset` 0.161 / `shuffled` 0.162——**二者等价**，这正是期望的：
状态若只提供通用偏置，喂错状态应与无状态相同。该对照设计正确。

### 2.4 发现 3：训练用的候选负例池依赖 `len(cand_pool[0])` 一致

`train_plan1.py` 假设同一 batch 内所有条目的候选数相同（`k = len(cand_pool[0])`）。
v3 数据满足，但 **SciFact 若每问证据数不同，此假设会失效**。
下一阶段必须改为变长候选。

### 2.5 发现 4：`first_step_states` 为逐条串行

1000 条约 4 分钟。SciFact 摘要更长、样本更多时会成为瓶颈。
状态必须逐条产生（这是被测对象），但**可分块并行**以提升吞吐。

### 2.6 可复用部分（保持不变）

- `RecurrentMemoryPooling` 与 `memory_output` 开关（默认 `new_slots`）
- `projection → normalize` 的嵌入路径（已修正，务必保留）
- 四条件评测骨架 `eval_plan1.eval_one`
- 数据校验框架 `check_plan1_data.py`（改字段映射即可）

## 3. SciFact 实验规格（已实施）

### 3.0 一个必须先说明的数据现实

**官方 SciFact 的 `claims_test` 只有 `{claim, id}`，没有标签**——三分类标签保留在隐藏评估服务器上。
可用带标签的数据是 `claims_train`（809）与 `claims_dev`（300）。

因此本实验**不能**沿用"官方 train / dev / test"三分，而是：

- 把 `claims_train` + `claims_dev` **合并**成标签池；
- 按**文档连通分量**重新划分为 train / val / test；
- **不使用**官方 test（无标签，无法评测）。

**这必须在论文中披露**：本实验的测试集是自建划分，不是官方 test split。

### 3.1 为什么按"文档连通分量"划分

按 claim 随机划分会让同一篇文献跨 split（实测 train/test 共享 **163** 篇文档）。
按文档哈希划分虽消除了重叠，但**丢样本严重**（只剩 106 条 test），
因为引用多篇文献的 claim 会跨越边界被丢弃。

最终方案：把"同一 claim 引用的文献"视为连通，
用并查集得到 document components，**整块组件**分配到 split。

结果：

| 划分 | n | NEI | SUPPORT | CONTRADICT |
|---|---|---|---|---|
| train | 716 | 256 | 299 | 161 |
| val | 164 | 79 | 61 | 24 |
| test | 228 | 81 | 95 | 52 |

**文档重叠：train/val 0，train/test 0，val/test 0。**

### 3.2 泄漏检查结果（L1–L5 全部通过）

| 检查 | 结果 |
|---|---|
| L1 claim 不出现在阶段文本中 | **0**（剔除 1 条 claim 原文出现在摘要中的样本） |
| L2 阶段文本无标签标注 | **0** |
| L3 文档级划分两两重叠 | **0 / 0 / 0** |
| L4 仅凭 claim 的词面基线 | Macro-acc **0.399**（多数类 0.417）✅ 无捷径 |
| L5 常量预测器 Macro-F1 | **0.196**（必须明显超过） |

> **L2 的检查方式已修正**：最初用"support/contradict 词是否出现"判泄漏，
> 命中 105/1109 条——但这两个词在科学文献里是**普通词汇**
> （"these data support our hypothesis"），不是标签泄漏。
> 改为检查**标签标注形式**（如 `LABEL: SUPPORT`、`[CONTRADICT]`）后为 0。

### 3.3 任务形式

```
阶段 1：读摘要前半 → s_1
阶段 2：读摘要后半 → s_2
阶段 3：输入 claim → 三分类
```

claim 在阶段 3 之前**从未出现**（L1 已验证）。

### 3.4 四条件

| 臂 | 阶段 3 的状态 |
|---|---|
| `carried` | `s_2`（真实两阶段状态） |
| `reset` | `None` |
| `shuffled` | 其他样本的 `s_2` |
| `concat` | 两块一次性读入（512 token），阶段 3 同样有第二步前向 |

### 3.6 结果（3 种子，228 条测试）

**主指标 Macro-F1**（常量预测器基线 0.196）：

| 条件 | 均值 | 标准差 | 每种子的值 |
|---|---|---|---|
| **carried** | **0.3151** | 0.0408 | 0.342 / 0.268 / 0.335 |
| shuffled | 0.2866 | 0.0193 | 0.265 / 0.301 / 0.295 |
| concat | 0.2953 | 0.0259 | 0.283 / 0.278 / 0.325 |
| reset | 0.2553 | 0.0227 | 0.281 / 0.248 / 0.237 |

每类 F1（种子 2，可见各类差异）：

| 条件 | NEI | SUPPORT | CONTRADICT |
|---|---|---|---|
| carried | 0.378 | 0.384 | 0.243 |
| reset | 0.197 | 0.139 | **0.374** |
| shuffled | 0.333 | 0.319 | 0.232 |

**注意**：没有任何条件退化为常量预测（都明显超过 0.196），但
reset 的类别分布与其他条件不同（NEI/SUPPORT 低、CONTRADICT 高）。

### 3.7 配对差值（预注册判据：3 种子同号 + CI 不含 0）

| 种子 | carried−reset (MacroF1) | carried−shuffled (MacroF1) | carried−concat |
|---|---|---|---|
| 0 | +0.061 | +0.077 ✅ | +0.059 |
| 1 | +0.020 | **−0.032** ❌ | −0.010 |
| 2 | +0.099 | +0.041 ✅ | +0.010 |

accuracy 层面的 bootstrap 95% CI（按测试样本）：

| 种子 | carried−reset | carried−shuffled |
|---|---|---|
| 0 | [−0.044, +0.048] **含 0** | [+0.0088, +0.110] 排除 0 |
| 1 | [−0.004, +0.101] **含 0** | [−0.075, +0.004] **含 0** |
| 2 | [+0.000, +0.162] 排除 0 | [+0.000, +0.092] 排除 0 |

### 3.8 判定：**未满足预注册标准**

```
记忆有效 <=> carried 在 Macro-F1 上同时优于 reset 和 shuffled，
             且 3 个种子的配对差值同号，bootstrap 95% CI 不含 0
```

- `carried > reset`：3/3 同号 ✅
- **`carried > shuffled`：2/3 同号 ❌**（种子 1 为 −0.032）
- accuracy CI：3 个种子中有 2 个包含 0

**结论：在 SciFact 上，跨输入记忆的收益未达到预注册的显著性标准。**

### 3.9 如何解读（严格表述）

| 主张 | 判定 |
|---|---|
| 合成任务上的机制有效 | ✅ 成立（carried−reset +0.331，3/3 同号，CI 排除 0） |
| 机制在 SciFact 上有**方向性**迹象 | ⚠️ carried 均值最高（0.315 vs 0.255/0.287） |
| 机制在 SciFact 上**统计显著** | ❌ **不成立**（shuffled 对照不同号，CI 含 0） |
| 合成实验是假的 | ❌ 不能这样说——两者任务不同、样本量差 4.4 倍（1000 vs 228） |

**可能的解释（并列，均未验证，不可择一归因）**：

1. **测试集规模**：228 条时 `carried−shuffled` 的种子间波动（−0.032 ~ +0.077）
   与整体标准差（0.04）同量级；
2. **对初始化敏感**：种子 1 的 reset/shuffled 明显高于其他种子，
   可能反映了训练不稳定，而非样本量问题；
3. **对数据划分敏感**：当前是单一划分（连通分量一次分配），
   换一种划分（多种子重划分）可能给出不同结论；
4. **机制本身不适用于该任务**：SciFact 摘要短，两块一次即可读完，
   记忆机制本来就没有发挥空间。

**评审指出的一点必须采纳**：不能把未达标直接归因于样本量。
以上四条中，(1) 与 (2)(3) 在观测上无法区分——
若要区分，需要的是**换多种数据划分**（同一测试集规模），
而不只是增加种子。

**这不否定合成实验，也不构成对真实任务的正面证据。**
它是"当前机制的收益尚未在真实文本任务上得到确认"。
