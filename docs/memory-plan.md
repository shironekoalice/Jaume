# Jaume-Memory 实验计划（v0）

> 状态：JM-S 已完成并判定不通过（见 [memory-results.md](memory-results.md)）；JM-R 未开展。
> 试验台：Jaume-Embedding 350M（291.9M 参数，已发布 checkpoint 见根目录 README）。
>
> 本文回答两个独立问题：**JM-S** —— 可学习记忆槽能否改善语义 Embedding；**JM-R** —— 记忆跨输入传递能否产生额外收益。两者分开验证，初代不合并。

## 1. 问题定义

### 1.1 动机

Agent 的记忆与 RAG 管线里，文本以"块"为单位进入系统：单块要编码得准（检索用），多块之间的关系要留得住（记忆用）。现有两类做法各有短板：

- **普通池化**（mean / attention）对单块编码很强，但对"这一块相对整体文档处于什么位置、哪些内容值得留下"没有任何显式机制；
- **长上下文一次编码**成本随长度平方增长，且部署端（向量库）只接受定长向量。

Jaume-Memory 的假设：在 encoder 之上加一组**可学习的潜在记忆槽**，可以让定长向量输出在"有损压缩长输入"这件事上比普通池化做得更好；若进一步让状态**跨输入传递**（JM-R），还能覆盖连续输入场景。

### 1.2 JM-S（Latent Memory Pooling）

单输入。在 encoder 顶层 hidden states 上，用 N 个可学习槽向量做 cross-attention，输出 N×D 的槽表征，池化为最终向量：

```text
hidden states ──┐
                ├─→ Cross-Attention(N slots) ─→ slot states ─→ Pool ─→ Projection ─→ L2
learned slots ──┘
```

对照物是同样以 hidden states 为输入的 Mean / CLS / Attention Pooling。

### 1.3 JM-R（Recurrent Memory）

多输入。文档切块后依次编码，第 t 块的槽状态经过门控更新后作为第 t+1 块的槽初始值：

```text
slots_t ──→ Gate(∘) ──→ slots_{t+1}        （块间传递）
              ↑
       new slots_t（第 t 块编码产出）
```

门控与显式 reset 是第一版的全部记忆管理，不做长期记忆调度。

## 2. 评测隔离（先于一切训练）

**背景**：STS-B 与 STS22 在 350M 历史管线中多次用于挑选 checkpoint（见 PLAN.md 已知问题 1），属于污染集，只能作 dev/回归参考。

| 角色 | 数据集 | 用途 |
|---|---|---|
| 独立 holdout（英文 STS） | SICK-R | 论文数字 |
| 独立 holdout（检索） | BEIR SciFact（或 NFCorpus） | Recall@10 / nDCG@10，论文数字 |
| 独立 holdout（中文 STS） | C-MTEB STS 中选一（开工时定版本） | 论文数字 |
| dev（只许调参） | STS-B / STS22 | 调试、过拟合监控 |

规则：

1. holdout 只在整个实验系列结束、方案冻结后跑一次；
2. 任何用于决策（选槽 Neural 数、选 checkpoint、早停）的数据自动降级为 dev；
3. 固定数据集版本、划分、`max_length`、相似度函数，评测脚本入库（`scripts/evaluate_holdout.py`），bootstrap 1000 次报置信区间；
4. 训练/挖掘数据与 holdout 做近重复检查（n-gram 重叠）。

## 3. 基座与公平性

- 所有对照臂（B0–B6）使用**同一 MLM 基座 init**（当前新一代 350M MLM 基座在训；基座完成前允许先用现有 `350m-stage3` 跑通管线与测方差，正式数字以新基座重跑为准）；
- 相同训练数据、优化器、步数、随机种子（≥3 seed，报 mean±std）；
- 记忆模块的额外参数计入对照（B2 attention pooling 允许配到与 JM-S 槽模块参数量相当）；
- MoE 在所有臂中**保留但冻结为常量**：不新增 MoE 相关消融，不调 load-balance 系数。第一版不研究 MoE 与记忆槽的交互；
- 每个方案记录：参数量、吞吐（pairs/s）、峰值显存、推理延迟。不只比准确率。

## 4. 基线模型：必须回答"为什么要用记忆槽"

所有对照模型尽量使用相同的 Encoder、训练数据、优化器、训练步数和随机种子。

| 编号 | 模型 | 用途 |
|---|---|---|
| B0 | Mean Pooling | 常规基线 |
| B1 | CLS / EOS Pooling | 特殊 Token 池化基线 |
| B2 | Attention Pooling | 学习式池化基线（350M 现役池化，历史参照 STS-B 0.6223 @512D） |
| B3 | Latent Memory Pooling | 核心 JM-S |
| B4 | Latent Memory + MRL | 验证多维度输出收益 |
| B5 | Recurrent Memory | 核心 JM-R |
| B6 | Recurrent Memory + Gate | 验证门控更新是否必要 |

B2 是关键对照：如果 JM-S 只比 Mean Pooling 好却无法超过参数量与计算量相近的 Attention Pooling，只能证明"学习式池化有效"，不能证明记忆槽有特殊优势。

JM-R 必须与以下方案比较：

1. 不传递记忆，每块独立编码；
2. 直接拼接前后文本，在可用上下文范围内编码；
3. 只传递上一块的 Embedding；
4. 传递完整记忆槽并使用门控更新。

## 5. 数据集与评测方案

分三层：

### A. 语义表示质量

- SICK-R（英文，独立 holdout）、STS-B（dev）、C-MTEB STS（中文，独立 holdout）
- 指标：Spearman

### B. 向量检索能力

- BEIR SciFact（或 NFCorpus，独立 holdout）、C-MTEB 检索任务
- 指标：Recall@k、MRR@10、nDCG@10
- 检索评测只需编码 + 暴力搜索，单卡甚至 CPU 可跑

### C. 跨输入记忆能力（JM-R 专属）

可控合成数据 + 真实长文档，测六件事：远距离事实检索、多块信息整合、重复/冲突信息、无关文本干扰、状态重置与文档间隔离、输入顺序鲁棒性。

每次实验保存：配置、随机种子、Git commit、模型权重哈希、训练日志、评测结果。

## 7. JM-R 的关键：防止记忆污染

跨输入状态传播的副作用必须按三种能力分别测量：

- **保留**：新输入无相关信息时，旧信息是否仍可用？
- **更新**：新输入明确修正旧事实时（价格 100 → 120 元），状态能否更新而不无条件覆盖全部历史？
- **隔离**：切换文档/用户时，旧状态是否污染新任务？显式 reset 由数据边界（doc/session id）触发，第一版不做边界检测。

记忆槽是有损压缩：不保证准确保留实体、数字、时间与原文细节。需要精确引用的应用，由 Embedding 负责语义检索、外部存储负责原始事实。

## 9. 成功标准（训练前预注册）

- **JM-S 成功**：相对同 encoder 强池化基线（尤其 B2），SICK-R / SciFact / C-MTEB 上稳定改善，无明显其他任务退化；
- **JM-R 成功**：相同总输入长度与计算预算下，跨块事实检索或信息整合优于独立编码与简单状态传递，且不明显破坏已有记忆；
- **记忆槽有独立价值**：相对参数量、训练预算相近的 Attention Pooling，存在可重复收益（≥3 seed，多测试集一致）；
- **工程成功**：可复现、可部署，延迟/显存可测量，输入输出接口清晰。

具体提升幅度阈值不预先指定，以基线方差、数据集规模与计算成本共同确定；但判定用的数据集与指标以本文第 2/5 节为准，不得事后更换。

## 10. 路线

- JM-S 证明可学习记忆槽改善语义 Embedding → 长期可成为 Jaume 语义表示基础；
- JM-R 证明跨输入记忆传递的额外收益 → 长期作为长上下文、连续输入与 Agent 记忆研究的实验平台；
- Matryoshka 让同一模型支持不同向量存储/检索预算（复用现有 `MatryoshkaLoss` / `forward_matryoshka`）；
- 初代把两个问题分开验证，实验结束后再决定是否合并为统一架构。
