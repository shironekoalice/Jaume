# 突破性诊断：为什么训练一直失败，以及状态传递的真实效果

> 日期：2026-10-19
> 脚本：`diagnose_composition_learning.py`、`sweep_lr.py`、`run_frozen_head.py`、`run_state_on_frozen.py`
> **本节是对九次运行失败原因的完整追查，并给出更干净的测量结论。**

## 0. 核心结论

**问题从来不是"任务不可学"，而是"全量微调破坏了一个本来就有信号的表示"。**

在冻结编码器、唯一变量是状态传递的条件下：

| 条件 | test F1（split0/seed0） |
|---|---|
| **static（不传状态）** | **0.2924** |
| carried（传状态） | 0.2125 |
| shuffled（错状态） | 0.1793 |
| BM25（零训练参照） | 0.322 |

**不传状态最好，传状态反而降 0.080。**

## 1. 诊断链条（四步）

### 1.1 编码器本身有信号（C1）

零训练测量：

```
cos(gold block)  = 0.5931
cos(other blocks)= 0.5724
separation       = +0.021  (后期复测 +0.034)
gold-block rank  = 3.42  (随机 6.0)
rank==1 比例     = 27.5%
```

**预训练编码器已经把问题与证据块拉近了。** 这否定了
"任务对 350M 编码器太难"的假设。

### 1.2 训练目标病态（C2）

- 120/120 条样本的 gold 集合包含 **>1 个块**
- 训练却用 `gold_blocks[0]` **单个正类**
- 总正确目标 265 个，训练信号只用 120 个（**45%**）

**55% 的正确块被损失函数主动推开。**

### 1.3 全量微调破坏信号（关键）

改用多标签 BCE 后，loss 确实开始下降（5.91 → 2.64），
但测试 F1 仍停在 0.15。

学习率扫描（多标签目际，1 epoch）：

| lr | loss | train_f1 | test_f1 | **分离度 sep** |
|---|---|---|---|---|
| **1e-5** | 10.17 | 0.195 | **0.2096** | **+0.0044** |
| 3e-5 | 19.34 | 0.148 | 0.1511 | +0.0032 |
| 1e-4 | 23.56 | 0.107 | 0.1598 | **−0.0000** |

**未训练时 sep = +0.021，所有学习率训练后都降到 ≤ +0.0044。**

**训练在学习率上均匀地破坏表示质量**，且 lr 越大 loss 越高。

梯度检查显示梯度健康（总范数 14.3，投影层 4.91），**不是梯度问题**。

**结论：514 条训练样本上全量微调 350M 模型 = 过参数化微调，破坏预训练表示。**

### 1.4 冻结骨干 + 轻量头（验证）

冻结编码器，只训练 524.8K 参数的成对打分头：

```
ep  0  test_f1 0.1891
ep 10  test_f1 0.2115
ep 39  test_f1 0.2154
```

**3 分钟训练即达 0.215**，优于全量微调训练 25 分钟的最好成绩（0.21）。
**证实了"问题在微调，不在特征"。**

## 2. 冻结特征上的状态对照（最干净的测量）

### 2.1 为什么这次测量是干净的

| 之前的干扰 | 本次状态 |
|---|---|
| 全量微调破坏表示 | ❌ 已消除（骨干冻结） |
| 训练目标病态 | ❌ 已消除（多标签 BCE） |
| 训练预算不足 | ❌ 已消除（40 epoch / 170 秒） |
| 编码器无信号 | ❌ 已排除（sep +0.021） |

**唯一变量：块表示是否经过状态传递。**

### 2.2 结果

| 条件 | test F1 |
|---|---|
| **static**（块自身池化向量） | **0.2924** |
| carried（状态，读到该块为止） | 0.2125 |
| shuffled（错的状态） | 0.1793 |

**配对差值**：
- `carried − static` = **−0.0799**
- `carried − shuffled` = **+0.0331**

### 2.3 如何解读

1. **`carried > shuffled`（+0.033）**：状态里**确实携带了与当前论文相关的信息**
   （错的状态更差）。这确认了状态传递是有效的、非随机的。

2. **但 `static` 比两者都好（0.292）**：**不带历史的状态表示，
   比"包含历史的状态"更能定位证据块。**

3. 这一现象与之前所有观察一致：
   状态是**累积和**，读到第 i 块时，`state_i` 混入了前面所有块的内容，
   于是**块 i 自身的辨识度被稀释**。
   用这样的表示去找"哪块含证据"，自然不如直接用块 i 自己的向量。

**这说明：状态不是"没用"，而是"不适合当作单块的表示"。
它的价值应该在别处（例如表示整篇文档），而不是替代单块表示。**

## 3. 对 JM-R 的关键启示

| 发现 | 含义 |
|---|---|
| 状态携带论文级信息（carried > shuffled，+0.033） | ✅ 机制确实在工作 |
| 状态不适合作单块表示（carried < static，−0.080） | ❌ 但当前用法错了 |
| 全量微调破坏预训练信号 | ⚠️ 之前所有训练结论都受此影响 |

**之前的九次运行、SciFact、Qasper 全量实验，全部在
"全量微调破坏表示"的条件下进行**——这解释了为什么它们一致失败。

## 4. 下一步（有依据）

**不要再用状态替代单块表示。** 应该：

1. **单块表示用 `static`**（最优，0.292）；
2. **状态用于论文级任务**：例如"这篇论文是否包含答案"、
   或作为 **reranking 的全局上下文**；
3. 若要用状态增强单块，应**拼接**而非替代：
   `repr_i = [static_i ; state_i]`，让模型自己选择用哪个。

### 6.3 最终判定

| 主张 | 判定 | 证据 |
|---|---|---|
| 状态携带论文级相关信息 | ✅ **成立** | carried > shuffled，+0.032，5/5 |
| 状态传输有效、非随机 | ✅ **成立** | 错状态一致更差 |
| **状态适合作单块表示** | ❌ **不成立** | carried < static，−0.079，5/5 |
| 编码器语义表示优于 BM25 | ❌ **不成立** | static 0.28–0.31 vs BM25 0.32 |

### 6.4 对 JM-R 路线的含义

**这不是"记忆机制无效"，而是"记忆状态被用错了地方"。**

- 状态确实在传递信息（机制本身在工作）；
- 但它把整篇论文的内容累积进来，**稀释了当前块的辨识度**；
- 用它替代单块表示去回答"哪块含证据"，必然劣于直接用块自己的向量。

**正确用法**：单块任务用 `static`；状态用于**论文级/跨块组合任务**，
或作为**拼接特征**而非替代。
