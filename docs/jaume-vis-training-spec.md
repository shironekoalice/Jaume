# Jaume-Vis 系列训练规格（v1.0）

> 撰写日期：2026-11-11
> 依据：Jaume 三个方向的完整实测（loop / VLM / OCR / 检测）
> 定位：**可执行的训练配方**，不是研究提案。每条都标注了证据来源。

---

## 0. 一句话结论

**Jaume-Vis 不要自研基座。** 用现成的强 VLM 基座（Qwen3-VL 级别），
在它上面做结构化能力扩展（坐标 token + 像素解码器），
把算力投在数据和能力协议上，而不是从零预训练。

这个结论来自 Jaume 的实测：350M 自研基座在语义上够用（0.954），
但在字形（0.21）和精确定位上需要专用塔和显式坐标，
而从零把基座训强所需的算力远超我们的预算。

---

## 1. 基座选型

### 1.1 三条路线的实测对比

| 路线 | 证据 | 结论 |
|---|---|---|
| 自研 350M 基座 | loop-spec 8.9：8 层饱和；VLM 需双塔 | 可行但天花板低 |
| 现成 Qwen3-VL + 结构化头 | WeVisOne-VL 2B 已证明 | **推荐** |
| 从零训 2B+ | 未见证据；算力估算远超 100 卡时 | 不做 |

### 1.2 具体建议

| 项 | 选择 | 理由 |
|---|---|---|
| 文本基座 | Qwen3-VL 2B 或同级 | 省掉预训练；语义能力已验证 |
| 视觉塔 | 基座自带（Qwen 的 ViT） | 避免双塔的融合成本 |
| 词表扩展 | 字符表 + 坐标 token + 实例分隔符 | 见 §3 |
| 可训练部分 | projector + 顶部 k 层 + 能力头 | 61GB 单卡可跑 |

**不要做的事**：不要在自己训的 350M 上堆能力。
实测表明那会陷入「补了 A 掉 B」的多任务冲突（vlm-dual-tower-spec 6b）。

## 2. 预训练目标

### 2.1 必须做因果语言建模（关键教训）

Jaume 的基座是 MLM 预训练，**checkpoint 里没有 lm_head**。
这导致所有下游任务都要从零学输出层，低数据时极不稳定
（loop-spec 8.12b 的记录）。

**Jaume-Vis 必须**：

1. 预训练阶段就用 next-token prediction
2. **保存 lm_head 权重**（不要只存 backbone）
3. 下游微调时复用预训练头，而不是随机初始化

### 2.2 长度课程（已验证有效）

| 阶段 | 序列长度 | 占比 |
|---|---|---|
| 热身 | 256 | 15% |
| 主体 | 1024 | 35% |
| 长文 | 2048 | 25% |
| 长文 | 4096 | 25% |

证据：Jaume 用这个课程训练，loss 从 67.5 单调降到 11.8，
且 4096 长度不 OOM（context-length.md）。

### 2.3 上下文能力

| 项 | 数值 | 证据 |
|---|---|---|
| RoPE theta | 1e6 | 4096 训练后 16K 推理不崩 |
| 实测可用 | 16384 | context-length.md |
| 建议训练覆盖 | 4096-8192 | 平衡显存与能力 |

**不要用 8192 训练**：显式注意力需要 [B,H,8192,8192] 分数矩阵，
61GB 卡会 OOM（已实测）。4096 是安全上限。

## 3. 能力协议（最重要的一节）

### 3.1 坐标 token 必须高精度

实测的量化上限（vlm-dual-tower-spec 6j）：

| 网格 | IoU>0.3 通过率 | 说明 |
|---|---|---|
| 8x8 | 0.763 | 我们用的，IoU 只到 0.347 |
| 16x16 | 0.999 | 可用 |
| 32x32 | 1.000 | 推荐 |

**Jaume-Vis 应该用 1000 级坐标 token**（WeVisOne 的做法，<0>..<1000>），
而不是我们试的 8 级。精度直接决定检测上限。

### 3.2 结构化输出格式

| 能力 | 输出格式 |
|---|---|
| 计数 | 单个数字 |
| 检测 | <OBJ><x1><y1><x2><y2> 重复 |
| 定位 | <OBJ><cx><cy> 重复 |
| OCR | 文本（逐字符自回归） |
| 分割 | <OBJ> + mask token |

<OBJ> 分隔符是关键——它让密集小目标可表达
（WeVisOne 的核心设计，见 deepseek-technique-audit.md §3）。

### 3.3 解码必须是自回归

实测对比（vlm-dual-tower-spec 6k）：

| 解码方式 | funsd_read |
|---|---|
| 单点读出（一个向量预测所有字符） | 0.11 |
| **自回归（答案前缀作为输入）** | **0.281** |

**2.6 倍差距。** 开集任务（答案不固定）必须自回归。

## 4. 视觉处理

### 4.1 保持宽高比（必做）

FUNSD 的 crop 宽高比从 0.29 到 13.4（46 倍差异）。
强行拉伸到正方形会毁掉字形。

**做法**：letterbox padding，保持原生比例。

### 4.2 不要指望语义塔做 OCR

实测（ocr-diagnosis.md）：

| 模型 | text_locate |
|---|---|
| SigLIP2 | 0.21 |
| InternViT-448 | 0.21 |
| **TrOCR** | **0.75** |

**分辨率不是主因**（InternViT 448px 也失败），**训练目标才是**。

### 4.3 OCR 的两条路

| 路线 | 做法 | 适用 |
|---|---|---|
| 外挂专用模型 | TrOCR/PaddleOCR 提文字，基座做理解 | **产品推荐** |
| 领域继续训练 | 对视觉塔做 OCR 数据微调 | 研究，成本高 |

**推荐外挂**——识别与理解分离，各自用最强工具。

## 5. 训练阶段

### 5.1 四阶段

| 阶段 | 数据 | 目标 | 判据 |
|---|---|---|---|
| **S0 对齐** | 合成图文 | projector 能工作 | 基础识图 >= 0.9 |
| **S1 能力** | 合成 + 真实图像 | 多能力并存 | 每项 >= 0.8 |
| **S2 领域** | 目标领域数据 | 产品可用 | 业务指标 |
| **S3 强化** | 难例挖掘 | 边界提升 | 长尾指标 |

### 5.2 多任务冲突的处理（关键）

实测（vlm-dual-tower-spec 6c）：

| 方案 | 效果 |
|---|---|
| 直接混合训练 | OCR 0.65，语义 0.95（OCR 被挤掉）|
| **任务条件化调制** | OCR 0.887 + 语义 0.913（并存）|

**做法**：用问题嵌入生成门控向量，动态混合多路特征。

    g = sigmoid(MLP(mean_pool(question_embedding)))
    fused = g * stream_a + (1-g) * stream_b
    x = [fused | stream_a | stream_b | question | answer]   # 残差保留

三个要素缺一不可：条件化门控 + 残差通路 + 任务权重平衡。

### 5.3 数据配比

实测（vlm-dual-tower-spec 6d）：

计数任务掉分的原因是**样本占比太低**，不是能力不足。
4 倍过采样后一个 epoch 就恢复。

**建议**：按任务难度而非自然分布配比。稀有但重要的能力要过采样。

## 6. 评估协议（容易被忽视但极重要）

### 6.1 不要用 exact match 评检测

实测（vlm-dual-tower-spec 6h）：

| 任务 | exact match | IoU/容差 |
|---|---|---|
| det_boxes | 0.058 | 0.158 |
| det_point | 0.109 | **0.504** |

**exact match 严重低估能力。** 检测用 IoU，定位用距离容差。

### 6.2 文本答案要归一化

真实文档 OCR 的大小写、空格、形近字差异会把正确读取判为错误：

| 标注 | 模型输出 | 是否算对 |
|---|---|---|
| Beauty Contest | BEAUTY CONTEST | 应该算对 |
| ATXO2 0083035 | ATX02 0083035 | 形近字，酌情 |

**做法**：upper() + 空格归一化后再比。

### 6.3 先做信息论可行性检查

在投入训练算力前，先用**线性探针**确认任务可解：

    冻结视觉塔 -> 提特征 -> 线性分类 -> 如果接近随机，任务本身不可解

这个检查只要 3 分钟，却省下了我们几小时无效训练
（ocr-diagnosis.md 的记录）。

## 7. 不要做的事（从失败中学到的）

| 不要做 | 证据 |
|---|---|
| 不要训思考链/循环 | loop-spec：8 种任务证明 8 层饱和 |
| 不要用语义塔做 OCR | ocr-diagnosis：SigLIP2/InternViT 都是 0.21 |
| 不要用 exact match 评检测 | 会低估 3-5 倍 |
| 不要在 8192 长度训练 | 显式注意力 OOM |
| 不要从零训 2B+ 基座 | 算力不够，且 WeVisOne 已证明用现成的更好 |
| 不要忽视宽高比 | 46 倍差异下拉伸会毁字形 |

## 8. 资源估算

| 阶段 | 卡时（910B3 61GB） | 说明 |
|---|---|---|
| 基座适配（projector + 顶部层） | ~2 | 冻结大部分 |
| 能力对齐（S0+S1） | ~10 | 合成数据为主 |
| 领域微调（S2） | ~20 | 真实数据 |
| 全流程首轮 | **~35 卡时** | 与我们已验证的量级一致 |

对比：从零预训练 2B 需要数千卡时。**这就是用现成基座的价值。**

---

## 9. 与 Jaume 的关系

| | Jaume | Jaume-Vis |
|---|---|---|
| 基座 | 自研 350M（MLM） | 现成 2B（Qwen3-VL 级）|
| 定位 | 验证组件与判据 | 产品化 |
| 价值 | 证明了双塔必要、坐标 token 有效、判据成立 | 继承这些结论直接做产品 |

**Jaume 的角色是探路，Jaume-Vis 是落地。**
Jaume 用最小成本验证了哪些路走得通、哪些走不通，
Jaume-Vis 不必重复这些试错。
