## 1. 方向定位与边界

Jaume-TTC 研究**单个输入内部**，改变 Transformer 层的执行序列能否换来有用的额外计算。

| 方向 | 研究对象 | 变异发生在 | 状态 |
|---|---|---|---|
| Jaume-Embedding | 静态单次前向的句向量 | —— | 已发布 v0.1 |
| Jaume-Memory（JM-S/JM-R） | 跨**输入**的状态通道 | pooling 层之间传状态 | 已结题，两机制均未通过 |
| Jaume-NM（Neuro-Memory） | 记忆的**结构**如何承载 | —— | 方向定义完成，未启动 |
| metamem | 外部写入策略 | 模型外部 | 暂停 |
| **Jaume-TTC（本文）** | **层执行序列**如何分配计算 | **backbone 层执行顺序** | 方向定义阶段 |

**关键区分（务必不要混淆）**：

- JM 的路径变异 = "多层之间是否传状态"，载体是 pooling 层的 `memory_state`；
- TTC 的路径变异 = "层本身的执行序列是否改变"，载体是 backbone 的 `layers` 遍历顺序。

两者**正交**，理论上可组合，但**不可互相替代**，不可合并成一个大实验。

## 3. 基座选择：**Jaume 350M 为主基座** [已决策 D1]

### 3.1 两者共享同一个 Hakus Transformer Core

`SPEC.md` §6 已定义：Tokenizer / Embedding / RMSNorm / RoPE / GQA / MoE / Expert Layer / Initialization / Checkpoint / Config **全部共享**；唯一区别是 attention 与输出形态。

| 维度 | **Loftey Mini 235M** | **Jaume 350M-stage3** | 对 TTC 的影响 |
|---|---|---|---|
| 来源 | `LightNeko/loftey-mini-235m`（MS）/ `Zeppesey/loftey-mini-235m`（HF） | 本 repo `350m-stage3/` | 都可直接取权重 |
| 许可 | MIT | 内部 | 都可商用 |
| **Attention** | **Causal（decoder-only）** | **Bidirectional（encoder）** | **决定能否做真 on-policy distillation** |
| **层数** | **6** | **16** | **决定路径空间与递归深度可行性** |
| hidden / inter | 512 / 2048 | 512 / 2048 | 相同 |
| heads / kv-heads | 16 / 8 | 8 / 4 | 不同 |
| experts / topk | 4 / 2 | 4 / 2 | 相同 |

| max_seq_len | 512 | 8192 | SciFact 91.7% 完整覆盖，512 可接受（§7.1） |
| 权重可得性 | `model.safetensors` 898 MB（LFS） | 本 repo 已具备 | ✅ |
| 任务 | 生成 | 表征 | 决定判别头挂法 |
| 预训练语料 | MiniMind（**中文为主**）[已核实 README] | 多语言 wiki + NLI | **英文 SciFact 能力未知 → 必须筛查** |

`Config` 类两边**逐字段同构**，只差 `model_type` —— 切换基座的代码成本接近零。

### 3.2 决策：为什么选 Jaume 而非 Loftey


**决策（2026-11-03，见 §3.4）：主基座 = Jaume 350M-stage3（双向）+ 自建 Jaume-Causal 350M（causal）孪生体，构成受控对照。**

**Loftey-mini-235M 不进首轮**（6 层太浅、中文语料、英文能力未知）。


五条理由，按权重排序：

| # | 理由 | 依据 |
|---|---|---|
| 1 | **层数是硬伤，不是细节** | 6 层的 REPEAT 是「把同一层跑两遍」，落在病态区域；16 层是在网络里**插入额外计算**。文献中 looped transformer 先例多在 12 层以上（730M/336B 的 Huginn vs Ouro 对比见 2610.23036）。路径空间 159 vs 44 条，REPEAT 粒度 +6% vs +17% —— **搜索空间与干预精度差一个档次** |
| 2 | **双向不是劣势，是特性** | 本方向的教师是**路径集成**（§4.2），两个基座都能用；rollout 只是 Gate 2 的附加对照项，不是主线。且双向在归因上**更干净**：同样的输入同样的输出，无采样噪声、无 teacher-student context mismatch，**唯一变量就是执行路径** |
| 3 | **科研资产完备度碾压** | Jaume 侧现成有：决策头、held-out 协议、泄漏检查 L1–L5（已实际跑通）、bootstrap CI、三阶段训练历史。Loftey 侧一切从零 |
| 4 | **规模与资产归属** | 350M > 235M；Jaume 是本项目自有资产，结论可直接进 README 与报告，不涉第三方许可链条 |
| 5 | **风险可控** | Jaume 侧基线已知（STS-B 0.6223）。Loftey-mini 是 MiniMind 中文语料训的 235M/6 层，**T0 筛查很可能直接不过** —— 用高风险支线承担主线的对标价值不划算 |

**Loftey 的保留价值（条件性）**：仅当 (a) Jaume 的 Gate 0 通过，**且** (b) 仍想验证「效应是否依赖 attention 形式」时，才作为**补充对照**接入，且必须先过 T0 筛查。不过则直接删除，不投入。

> **更精确的表述**：问题不在「Loftey vs Jaume」，而在「**6 层的 loftey-mini 不够格当 causal 基座**」。若将来要对标 LoOPSD 原味，需要的是 **12–16 层的 causal 预训练模型**，而非 loftey-mini。此项列为后续项，不进首轮。

### 3.2b 曾考虑过的「双基座并行」及其否决理由

初版曾提议 Gate 0 双基座并行（增量成本仅 ≈ 2 分钟），理由是能免费获得「效应是否依赖 attention 形式」的对照。**在 D1 决策后否决**：

- **收益不对称**：causal 侧结果的科学价值取决于 Loftey-mini 能否通过 T0（英文 SciFact 能力）。该前置不确定性若不成立，dual-base 的「对照」就退化成 single-base + 一个弱基座，**并无对照价值**。
- **注意力成本高**：首轮同时维护两套 backbone adapter、两套基线筛查、两套训练曲线，会显著稀释 Gate 1/2 的实施精力 —— 而这两个闸门才是真正的技术产出。
- **优先级排序**：先在最强基座上把 Gate 0→1→2 走通（Gate 2 需 4–6 周），比在浅基座上做对照更有价值。

**后续**：§3.4 的 **Jaume-Causal 孪生体**正是"12 层以上 causal 预训练模型"这一缺口的自建解法 —— 本节否决的只是"拿 Loftey-mini 充数"，而非 causal 对照本身。

### 3.3 Loftey-mini 的硬约束（**不进首轮**；记录在此以备日后查）

**Loftey-mini-235M**
- **只有 6 层** → 路径空间仅 ~43 条（Jaume 的 159 条）；REPEAT 最多 +6 层 = 100% 相对加深，粒度粗，且落在"同一层跑两遍"的病态区
- **MiniMind 中文语料** → 英文 SciFact 表征能力**未知**
- **max_seq_len 512** → 8.3% 样本截断
- **无评测基建、无决策头** → 需自建
- 权重可得（ModelScope / HF，MIT），但上述三条使其**不适合作为 causal 对照**，故不进首轮

**Jaume 350M-stage3**
- **bidirectional** → **没有 prefix 生成过程**，做不了真正的 token 级 on-policy distillation（首轮只能做表征级分布对齐）
- 16 层 → 路径空间大，适合递归深度类研究
- max_seq_len 8192，长上下文优势明显

### 3.4 决策补充：新建 **Jaume-Causal 孪生体** [已决策 D1b]

**决策（2026-11-03）：主基座 = Jaume 350M（双向）+ 自建 Jaume-Causal 350M（causal），构成孪生对照。**

#### 为什么必须新建（而不是沿用双向）

读 `code/repo/jaume/modeling/attention.py` 源码确认：`attn_mask` 只含 padding 分量，注释原文 `no causal component` —— **双向注意力每层每 token 看到全序列，没有可见性约束**。由此产生一个方法论上无法回避的混淆：

| | REPEAT 在双向 | REPEAT 在 causal |
|---|---|---|
| 第二遍的输入 | 第一遍输出，**仍全序列可见** | 上一遍思考结果，**只能看到已生成前缀** |
| 有无新信息约束 | **无** → 同一函数再作用一次 | **有** → causal mask 强制第 k+1 遍看到更多 |
| 净效果 | ≈ 在网络中部插入一次额外非线性变换 ≈ **局部加深** | **真正的迭代计算**（LoOPSD 所称"额外计算"） |

**后果**：在双向基座上，159 条路径里的 120 条（全部 REPEAT）**大概率只是"深度"的别名**，即 §10 的 **F5 在双向下是大概率事件而非小概率**。这会使机制的因果解释失效。

causal 基座同时解决三件事：
1. REPEAT 恢复"迭代"语义 → 机制研究对味；
2. **可直接对标** LoOPSD / SelfMorph / MACRO / LoopOPD（该领域全部工作在 causal LLM 上）；
3. 与 Jaume 构成受控对照 → 即使效应在两侧一致，"效应与 attention 形式无关"本身即是强结论。

#### 与 §3.2b 否决的"双基座"的区别（避免看似自相矛盾）

| | §3.2b 否决的方案 | 本节方案 |
|---|---|---|
| causal 侧来源 | **第三方弱模型** Loftey-mini-235M | **自建孪生体** |
| 深度 | 6 层（不够） | **16 层（与 Jaume 对齐）** |
| 语料 | MiniMind 中文为主（英文能力未知） | **与 Jaume 完全相同的 wikitext-103 + 中文维基** |
| 训练脚本 | 无 | **与 Jaume 完全相同的 `train_mlm.py`** |
| 前置不确定性 | 高（T0 可能直接不过） | **低**（除 attention 外一切对齐） |
| 可控性 | 无法控制预训练目标 | **完全可控** |

#### 孪生体的规格与成本（已核实）

| 项 | 值 | 来源 |
|---|---|---|
| 深度 / hidden / heads / kv | 16 / 512 / 8 / 4 | **与 Jaume 350m-stage3 逐字段相同** |
| 词表 / experts / topk | 151646 / 4 / 2 | 同 |
| 训练语料 | wikitext-103 + 中文维基，30 万句 | 同（`data/mlm_corpus.jsonl` 455 MB / 80 万行，实际训练 30 万句） |
| 训练脚本 | `train_mlm.py`（80/10/10 掩码，只对掩码位置投影 logits） | 同 |
| 语料 token 量 | ≈ 3840 万（30 万句 × max_length 128） | 估算 |
| **训练时长** | **4400 tokens/s → ≈ 2.4 小时** | `PLAN.md` 实测速度 |
| 显存 | ≤16GB 可跑 | 350M + bf16 + 梯度检查点 |
| **代码改动** | `attention.py` 加 causal mask **≈ 5 行**；config 加 `causal` 开关 | 已读源码确认 |

**总成本：改代码半天 + 训练 2.4 小时 + 评测 1 天 ≈ 2 天。** 这把"要不要建基座"从"几周"降级为"两天"。

#### 孪生体的两项已知风险（必须如实报告）

| 风险 | 说明 | 应对 |
|---|---|---|
| **causal 孪生体在判别任务上可能弱于双向** | causal 只看前缀，对"证据二分类"这类需要全局比对的任务天然不利 | T0 筛查不过 → **Jaume-Causal 降级为机制参考，主基座仍是 Jaume**。这本身是有信息量的结论（"判别任务上双向占优"），须写入报告 |
| **MLM 语料不含推理/数学语料** | 孪生体不会有强推理能力 | 首轮 Gate 0 只需判别任务有非随机基线，**不需要强推理能力**；若日后要做生成式推理任务，另需补语料（另立 spec） |

## 4. 核心技术机制

### 4.1 问题的重述

LoOPSD 的核心逻辑是：**额外计算 → 更好的教师 → 学生学到教师优势**。
在自回归设定下，"更好的教师"由"教师预测分布更有用"定义，教师由搜索产生。

**在判别式设定下如何定义"更好的教师"？**

### 4.2 教师定义：路径集成 [本系列主张]

> **教师 = K 条不同层执行路径输出的集成（ensemble）**
> **学生 = 单条路径的输出**

**为什么这个定义成立**：

1. **无需标签**。集成优于其成员是统计事实，不依赖 ground truth → 构造教师**零标签泄漏**。
2. **额外计算的含义清晰**：K 条路径 = K 倍前向算力，正是"测试时计算"的定义。
3. **与 LoOPSD 精神一致**：教师与学生**共享同一份权重**，差别只在执行路径。

**为什么它必须配 placebo**：集成增益有两个来源——(a) 集成本身降低方差；(b) 路径选择**针对问题**。必须把 (a) 扣掉，才能谈 (b)。

> **注意这是与原版 LoOPSD 的一处刻意偏离**：LoOPSD 的教师是"**搜索出的最优路径**"（需要带答案的样本筛选），本方向用"**路径集成**"（不需要标签）。
> 代价：教师不是单一最优路径，是集合；收益：零标签泄漏、可在判别式任务上运行。
> 在 causal 基座上，Gate 2 阶段会**额外**补一个"搜索出的最优路径"教师作为对照，以确认这个偏离没有损失关键效应。

### 4.3 路径空间的精确定义

统一表示为**层索引整数序列** `path = [i_0, i_1, ...]`，前向为 `for i in path: h = layers[i](h)`。与 `JaumeBackbone.forward` 现有层遍历结构直接兼容（改动量 ≈ 5 行）。

| 路径类型 | 定义 | Loftey (6 层) | Jaume (16 层) |
|---|---|---|---|
| `BASE` | `[0..L-1]` | 1 | 1 |
| `REPEAT(i,j)` | 在 BASE 中把连续区间 `[i..j]` 紧接其后**再执行一遍** | C(6,2)=15 | C(16,2)=120 |
| `SKIP(i)` | BASE 去掉第 i 层 | 6 | 16 |
| `REORDER` | BASE 的随机置换（固定 seed 生成 20 个） | 20 | 20 |
| `ITERATE(n)` | BASE 整网重复 n 次 | 2 | 2 |
| **合计** | | **~44** | **~159** |

`REPEAT(i,j)` 与 LoOPSD 的层循环语义一致（LoOPSD 例：L1→L2→L3→**L2→L3**→L4→L5）。

**注意 REPEAT 改变算力**：|path| ≠ L。所有比较必须**按前向层数做算力匹配**（§6 对照 3）。

### 4.4 实现代价估计

| 步骤 | 算力 | 估算 |
|---|---|---|
| 枚举全部候选路径 × train-split 子集 200 条 | 159×200 ≈ 31,800 次前向 | 350M、seq 512、batch 32，按 500 samples/s 计 ≈ **1–2 分钟** |
| Gate 0 的 4 个条件 × 3 seed × 完整 test 228 条 | 可忽略 | 分钟级 |
| Gate 1 选择器训练 | 单卡 16GB 可跑 | 冻结 backbone，只训选择器 + 分类头 |
| Gate 2 蒸馏（causal 基座，可做真 on-policy） | 教师 K 条 no-grad + 学生前向+反传 | 16GB 偏紧，22–32GB 舒适 |

**结论：Gate 0 是纯诊断、无需训练，1–2 分钟即可完成 159 条路径全量枚举。全流程不需要多卡。16GB 起，22–32GB 舒适。**

## 5. 三阶段闸门与冻结判据

每道闸门**独立可交付**，含负结果。任一闸门不过，**该线停止**，不进入下一闸门。

**主基座 = Jaume 350M-stage3（双向）+ Jaume-Causal 孪生体（causal）**，二者除 attention 形式外逐项对齐（§3.4）。


### Gate 0 — 归因：集成的增益有多少是"问题特异的"？（预计 1–2 周）

**主问题**：路径选择的增益，能否与"任何路径集成都能带来的方差缩减"区分开？

**四个条件**（同一基座内，同一模型、同一评测代码、同一数据划分）：

| 条件 | 定义 | 角色 |
|---|---|---|
| **A** | 单条最优固定路径（在 train-split 上选出） | 基线 |
| **B** | **input-blind 固定路径集成**（K 条，不看输入选） | **placebo（强制）** |
| **C** | 等算力随机路径集成（K 条随机种子） | 随机基线 |
| **D** | **oracle 路径选择**（用 label 逐样本选最优路径） | **上界** |

**D 用 label，仅作上界，绝不进入任何训练流程（物理隔离，§6 对照 8）。**

**冻结判据**：

- **Gate 0a（必要前置）**：`D > C` 显著（bootstrap 95% CI 下界 > 0）。
  → 不过：**"按输入选路径"本身无意义**，该基座停止。
- **Gate 0b（核心）**：`D − B` 的 bootstrap 95% CI **下界 > 0**，且点估计 ≥ 2×SE。
  → 不过：**增益不是问题特异的**，该基座停止。
- **Gate 0c（记录项）**：`A > C`（是否存在哪怕固定路径的增益）—— 记录但不作为闸门。

**（若日后启用 Loftey 补充对照）**：


- **Gate 0x**：Jaume 基座通过 0a+0b → 进入 Gate 1；不通过 → 停止，输出负结果报告。
  - **Jaume-Causal 孪生体**独立判定：作为受控对照，结论用于回答"效应是否依赖 attention 形式"；其自身不过不阻塞 Jaume 主线。

- （Loftey 补充对照若启用）其独立判定，结论只作旁证，不参与主线决策

**Gate 0 的产出**：**一份归因表**（增益拆解为「方差缩减」vs「问题特异性」两部分）。无论正负都写报告。

### Gate 1 — 选择器：能否学出 per-input 的路径选择（预计 3–4 周）

**通过 Gate 0x 才启动。**

- 轻量选择器：读前 2 层 hidden state → 输出路径分布 / 路径 id
- **必须监控**（JM 门控退化教训）：选择器输出分布对输入的**标准差**；**所选路径的熵**。熵坍缩到常数 → 退化，如实记录
- **必须做因果干预**（2610.21182）：对选择器输出做**内容替换**（把 A 样本的选择结果套到 B 样本），看性能是否变化。只做探针可读性**不算数**

**冻结判据**：

- **Gate 1a**：学习到的选择器 > 条件 B（input-blind 集成），bootstrap 95% CI 下界 > 0。
- **Gate 1b**：选择器输出的**跨样本标准差 > 阈值**（开工前按 train-split 冻结，如 std > 0.1 × 路径数）。→ 不过：**退化成固定路径**，如实记录，**不得**宣称"问题特异的路径选择"。
- **Gate 1c（守门）**：原始 embedding 能力不退化（Jaume 侧用 SICK-R / STS22；Loftey 侧以其自身 held-out 似然报告）。

### Gate 2 — 蒸馏：能否把增益压回单次路径（预计 4–6 周）

- 教师：条件 D 形态的**路径集成输出分布**
- 学生：**标准单次路径**（|path| = L，算力 1×）
- 损失：**reverse KL**（对齐 CRISP / LoOPSD 的做法）
- **causal 基座（Loftey）额外做原味版**：学生 rollout 生成 prefix，教师在 prefix 上给 token 级预测，reverse-KL —— 这是 LoOPSD 的原式，直接可对标
- **bidirectional 基座（Jaume）做表征版**：学生/教师在表征分布上对齐（无 prefix 可用）

**冻结判据**：

- **Gate 2a**：学生在标准路径上的判别指标 ≥ 教师增益的 50%（阈值开工前冻结），且显著优于 BASE。
- **Gate 2b（守门）**：原始能力指标无显著下降。
- **Gate 2c（必须报告）**：学生的**隐式路径偏好**——是否等价于"选了一条固定路径"。若是，结论必须限定为"集成蒸馏到单路径"，**不得**宣称"学会了问题特异的路径选择"。

### 13.1 T0 前置筛查 — **PASS**（2026-11-03）

| seed | best val F1 | **test macro-F1** |
|---|---|---|
| 0 | 0.3682 (ep 3) | **0.3349** |
| 1 | 0.3443 (ep 3) | **0.3589** |
| 2 | 0.3575 (ep 3) | **0.3566** |

| 指标 | 值 |
|---|---|
| mean test macro-F1 | **0.3502** |
| range | [0.3349, 0.3589] |
| constant-predictor floor | 0.1961 |
| **结论** | **PASS —— 三个 seed 全部超过地板**，最高为地板的 1.83 倍 |

**这意味着**：causal 孪生体的冻结表征**确实携带 SciFact 三分类所需的信息**，不是随机基线。§5 的 Gate 0 前提（"得有信号才谈得上路由"）成立。

**注意**：这**不**说明层执行路径有用 —— T0 只测"有没有信号"，Gate 0 才测"信号能否被路径选择利用"。两者不能混淆。

### 13.2 Gate 0 归因 — **三轮迭代后的结论（2026-11-04）**

Gate 0 问的是：层执行路径的增益是**问题特异**的，还是**通用扰动**？三轮跑下来，评价协议本身修了两次，最终结论与最初一轮的表面 PASS **相反**。

#### 迭代记录（为什么不直接采信第一轮）

| 版本 | 协议问题 | 现象 |
|---|---|---|
| v1/v2 | placebo 用**随机抽取**的 K 条路径（混入 `skip_*` 等烂路径） | B=0.3401 低于单条最优 A=0.3690，集成输给单条，不合常理 |
| v3 | 改用 **val（仅 164 行）** 排序选 top-K | 仍出现 B(0.3179) < C(随机, 0.3580)，是典型的**选择过拟合** |
| **v4（采用）** | **train 内 5-fold CV** 排序；C 改为**全部候选路径**等权集成（零选择） | 用 3 个 seed 报告 sd 与 range，并做 C−A 的噪声判定 |

v4 同时把候选空间从 159 扩到 **174**，新增三类**结构性不同**的路径族，以排除"错误相关性太高"这一解释：

- `REORDER`（8 条）：固定种子全序列置换
- `BLOCKSWAP`（6 条）：交换两段连续层块
- `REVERSE`（6 条）：一段连续层逆序执行

#### v4 结果（3 seeds，Ascend 910B3）

| 条件 | 含义 | mean macro-F1 | sd | range |
|---|---|---|---|---|
| **A** | 单条最优固定路径（CV 选） | **0.3503** | **0.0041** | 0.0079 |
| **B** | top-8 集成（CV 选，input-blind） | 0.3448 | 0.0130 | 0.0228 |
| **C** | 全 40 条等权集成（零选择） | 0.3553 | 0.0140 | 0.0247 |
| **D** | oracle 逐样本选（**用标签，不可达**） | **0.7113** | 0.0079 | 0.0157 |

`D` 的 **coverage = 0.751** —— 75.1% 的测试样本存在某条候选路径能答对；24.9% 无论怎么选都没救。

#### 三条结论

**1. 集成本身没有增益。** `C − A = +0.0049`，而 seed sd 约 0.0140 —— **差值落在噪声内（NOT RESOLVED）**。且 `B < A`，精挑的 top-8 集成**低于**单条最优路径。

**2. 加路径多样性没有改变结论。** 新路径族确实进入 top-8（`skip_5`、`skip_7` 取代了部分 repeat），但 B 仍低于 A、C 仍不显著高于 A。这**排除了"错误相关性高导致集成失效"**的解释 —— 问题不在路径不够多样，而在**集成这个操作在判别任务上本身无效**。

**3. 条件信息大量存在，但 input-blind 方式取不出来。** oracle 达 0.7113，比 A 高 **+0.361**，覆盖 75.1% 的样本。但所有不看输入的组合（A/B/C）都停在 0.35 附近。

#### 对 Gate 1 的意义

Gate 0 的价值在于**把简单办法全部排除**：

- 固定路径 → 0.3503
- 好路径集成 → 0.3448（更差且更不稳）
- 全路径集成 → 0.3553（噪声内）

唯一可能拿到那 +0.36 的通道是**per-input 的条件化选择器**。因此 Gate 1 的判据变得清晰：

- **及格线**：超过 A（0.3503）
- **有效线**：显著超过 C（0.3553）
- **目标**：向 D（0.7113）靠近，但受 coverage 0.751 封顶

**风险前置声明**：coverage 高只说明"存在正确路径"，**不说明"路径选择信号可学"**。若 Gate 1 的选择器无法在无标签条件下判断该走哪条路径，则本方向以负结果收尾（F1）。

---

### 13.3 Gate 1 / Gate 1b — **负结果，方向结题（2026-11-04）**

Gate 0 之后，唯一剩下的通道是 per-input 条件化选择器。Gate 1 系列直接测这条通道，两次都失败。

#### Gate 1：前缀选择器

用路径前缀的隐状态训练一个选择器，让它在推理时按输入挑路径。

| 条件 | test macro-F1 |
|---|---|
| G1（学习到的选择器） | 0.3324 |
| G1-rand（随机选择，**同分布对照**） | **0.3483** |

**随机选择反超学习者。** 这不是"提升不显著"，而是**学习到的选择器比随机更差** —— 说明选择器拟合到的是与"哪条路径会答对"无关的信号（噪声/长度/位置偏差），泛化时变成有害。

#### Gate 1b：置信度自适应

不再训练选择器，直接用模型对自身输出的置信度决定用哪条路径 / 用多少预算。

| 预算 | adaptive（按置信度） | shuffle（打乱置信度，对照） |
|---|---|---|
| 16 | 0.3470 | **0.3826** |

**打乱置信度后反而更好。** 这是最干净的证伪：如果置信度真携带"该用哪条路径"的信息，打乱它必然变差。

#### 结题结论

| 问题 | 答案 | 证据 |
|---|---|---|
| 层执行路径的增益是问题特异的吗？ | **是** | D(oracle)=0.7113 vs A=0.3503，coverage 0.751 |
| input-blind 组合能拿到吗？ | **不能** | C−A=+0.0049 < sd 0.0140；B<A |
| per-input 选择器能拿到吗？ | **不能** | G1 被随机反超 |
| 自置信度能拿到吗？ | **不能** | 打乱置信度更好 |

**四条通道全部关闭。** 本方向以 **F1（负结果）** 收尾。

**可发表性**：这不是"实验失败"，而是一个有明确边界的诊断性结论 ——
**"小模型的条件化推理增益存在但不可提取，且自置信度是反信号"**。
它与文献 2610.10368（input-blind 对照）、2507.14417（inverse scaling）互相印证，
构成"test-time compute 不是免费的"这一主张的实证补充。
