# JM-R 状态信息探针：问题定位

> 日期：2026-10-17
> 脚本：`scripts/probe_state_shapes.py`、`scripts/probe_state_facts.py`、`scripts/probe_sanity.py`
> **未修改任何模型结构，未训练任何新记忆模型。** 只复用现有权重与状态提取路径。

## 0. 结论先行

**问题不在"状态里没有信息"，而在"状态从不参与输出"。**

准确地说：**JM-R 的代码里根本没有"读取状态"这一步。**
输出向量完全由当前块决定，状态只是被顺带保存下来。

这解释了 G3 中 `carried = reset = 0.158` 的全部现象。

## 1. 你问的细节：状态更新流程是什么

读过 `jaume/modeling/memory.py` 与 `embedding.py` 后的准确答案：

```
对每个块 t：
  new_slots = slot_pass(hidden_t, init = 上一块的 state)
       └─ 交叉注意力读一次（slot_iterations 默认 1）
       └─ 更新是纯残差：slots = slots + read
  [B6 额外] carry = gate(prev_state, new_slots)   ← 门控插值
  [B5]     carry = new_slots                       ← 上一块状态直接被覆盖

输出向量 output_t = pool_slots(new_slots) = mean(8个槽)   ← 只依赖 new_slots
返回状态 state_t  = carry
```

所以：

| 你的猜测 | 实际情况 |
|---|---|
| 每读完一块用 GRU 更新一次 | ❌ 不是 GRU。`slot_gru` 只在 `slot_iterations>1` 时启用，而默认是 1，**因此是纯残差** |
| 最后 8 槽均值池化 | ✅ **是**，`slot_pool="mean"` |
| 其他流程 | 有：B6 在残差之外还加了一层**门控插值** `gate(prev, new)` |

## 2. 实测张量形状

```
encode(chunkA, state=None) -> pooled (1, 512),  state (1, 8, 512)
encode(chunkB, state=s_A)  -> pooled (1, 512),  state (1, 8, 512)
```

状态是 **8 × 512 = 4096 维**，不是 512 维。

### 2.1 两个已经异常的观测

| 观测 | 数值 | 含义 |
|---|---|---|
| cosine(s_A, s_AB) | **0.97 / 0.97 / 0.95**（B5/B6/B3） | 读完块 B 后状态几乎没变 → 块 B 信息几乎没写进状态 |
| 槽间平均余弦 | **0.83 – 0.91** | 8 个槽高度雷同 → 实际信息量远小于 8 槽 |

## 3. 事实信息探针（核心）

用线性探针从各种表示预测**块 A 的两个数值**，80/20 划分，R²（常量预测器 = 0）：

| 表示 | 维度 | R² 值1 | R² 值2 |
|---|---|---|---|
| `pooled_A`（正常输出） | 512 | **0.3847** | 0.2931 |
| `state_A_mean`（状态槽均值） | 512 | **0.3847** | 0.2931 |
| `state_A_flat`（8 槽展平） | 4096 | 0.3342 | 0.3164 |
| `state_AB_mean` | 512 | 0.3807 | 0.3081 |
| `state_AB_flat` | 4096 | 0.3421 | 0.3242 |

### 3.1 探针本身的可靠性验证

在得出结论前先验证探针不是坏的（`probe_sanity.py`）：

| 检查 | 结果 | 期望 |
|---|---|---|
| 植入线性信号 | R² = **1.0000** | ~1.0 ✅ |
| 常量目标 | R² = −8.87 | ≤0 ✅ |
| 打乱标签 | R² = −3.01 | ≤0 ✅ |

**探针是有效的。**

### 3.2 决定性发现

```
max |pooled_A - state_A_mean| = 0.000000
cosine(pooled_A, state_A_mean) = 1.0000 (min = mean = max)
```

**`pooled_A` 与 `state_A_mean` 是同一个张量，逐位相同。**

代码层面完全解释得通：`pool_slots(slots) = slots.mean(dim=1)`，
而后端 `projection` 是固定的线性层 + LayerNorm，两者对同一输入必然给出同一结果。

**推论**：所谓"记忆状态"在输出端**不可见**。

## 4. 为什么 carried = reset（机制解释）

```
output_t = pool_slots(new_slots)
new_slots = slot_pass(hidden_t, init = state_{t-1})
          = state_{t-1} + read(hidden_t)      ← 纯残差，1 次迭代
```

代入：

```
output_t = mean(state_{t-1} + read(hidden_t))
         = mean(state_{t-1}) + mean(read(hidden_t))
```

- 第一项 `mean(state_{t-1})` 是一个**与任务无关的加性偏置**；
- 第二项 `mean(read(hidden_t))` 才是任务信息，**且它只依赖当前块**。

对块 B 而言，`read(hidden_B)` 完全不含块 A 的内容。
所以 `output_B` 中块 A 的信息**只通过那个加性偏置**进入——
而偏置对所有条目近似相同（因为 8 槽高度雷同、更新是残差），
经过 LayerNorm 后几乎被抹掉。

**结论：架构上没有"用状态去作答"的路径。**
`carried` 与 `reset` 的区别只是"初始槽不同"，
而初始槽的影响是**常数偏置**，不是条件信息。

## 5. 按你的分流规则，属于哪一类

| 情形 | 是否命中 |
|---|---|
| 块 A 可读、状态不可读 → 写入/门控/池化丢信息 | ❌ 不成立：状态 R² 与正常输出**完全相同** |
| **状态可读、下游失败 → 读取接口问题** | ✅ **命中** |
| 线性探针失败 → 用非线性复核 | 不适用（线性已能读出） |

**但比"读取接口有问题"更严重**：**不存在读取接口**。
状态被正确计算、正确保存、正确传递、信息也还在（R² 0.38），
但**没有任何代码把状态用于产生输出**。

### 5.1 补充测量：信息在槽结构里吗？（回应评审）

评审指出：`mean(state) == pooled` 只能证明两者是同一表示，
**不能**证明"槽间信息被池化丢弃"这一相反可能。
因此追加了槽结构探针（`scripts/probe_slot_structure.py`）：

| 读出方式 | 维度 | R² 值1 | R² 值2 |
|---|---|---|---|
| `mean`（模型当前输出） | 512 | 0.3847 | 0.2931 |
| `flat`（8 槽全拼接） | 4096 | 0.3342 | 0.3164 |
| `slot_wise_best`（最佳单槽） | 512 | **0.4149** | 0.3046 |

逐槽 R²（值1）：`[0.287, 0.266, 0.283, 0.390, 0.337, 0.306, 0.415, 0.339]`

**槽间余弦 0.9348（min 0.8675 / max 0.9784）**，
`std(mean)/std(slots) = 0.9705`。

**结论：信息不在槽的结构里。**
三种读出方式的 R² 基本持平（0.29–0.41），
8 个槽高度雷同，均值池化几乎无损。

**因此"均值池化是瓶颈"这一假设被证伪，
评审提出的 B 候选（保留槽结构的读出层）缺乏依据，未予实施。**

另注：分类目标（哪个协议数值更小）的 R² 为 **−0.077**（mean 读出），
即这个**比较关系**没有被状态编码，只有数值本身被编码——这一点在 P15/G3 中
也得到印证（模型必须借助 concat 才能比较）。

## 6. 为什么之前的训练没有自己学会

G3 里训练时 loss 4.09→3.83（几乎不降），而 `concat` 能到 0.476。
原因是：在 `carried` 条件下，模型无论怎么调权重，
**输出都拿不到块 A 的信息**（只有常数偏置），
所以 loss 无法下降——**这是架构决定的，不是训练不足**。

## 7. 针对性修复（每次只改一个因素）

按你的要求，只提一个最小修复方向，不直接实现：

**最小改动**：让输出真正依赖状态，例如

```python
# 现状
return self.core.pool_slots(new_slots), carry

# 最小修复候选（二选一，只改一处）
(A) 输出改为对最终状态池化，而不是对本块新槽池化：
    return self.core.pool_slots(carry), carry

(B) 加一个读出向量：把 state 与当前块表示拼接后过一层线性
```

**为什么 (A) 是"最小且唯一改变一个因素"的选择**：
它不改任何参数、不改门控、不改残差更新，
只把"输出从哪来"从 `new_slots` 改成 `carry`。
若 (A) 之后 `carried > reset`，则收益确实来自状态；
若仍相等，说明即使状态被正确读取，其内容也不足以作答，
那时再考虑 (B) 或改门控。

**必须保留原对照**：`concat` / `reset` / `carried` / `shuffled` 四项全部保留。

## 8. 关于"神经记忆 vs 产品长期记忆"

同意你的判断，并记录在此以免混淆：

- 本实验检验的是**现有状态机制能否帮助模型完成特定跨块任务**；
- 这与"神经记忆有没有价值"是不同的命题；
- 即使 JM-R 在此任务上失败，Jaume 仍可通过**外部持久化存储 + RAG + 任务状态管理**
  实现可靠的长期记忆，神经记忆可作为独立研究方向，**不必是产品前置条件**。
